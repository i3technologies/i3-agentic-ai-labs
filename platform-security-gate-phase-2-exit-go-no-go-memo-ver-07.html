Blocking Findings

BLOCKER-1 · SEC-09 (OPEN) · PGPASSWORD literal in docs HTML file

platform/docs/03-databases-storage-guide.html lines 485 and 492 contain the literal PostgreSQL password ?Z-EfajDpq21=G/5iR21>k8f. This is a non-gitignored tracked file. The password is in the git history regardless of whether the underlying DB credential has been rotated. P2-GATE-10 requires zero new Critical or High security findings.

Resolution: (1) Rotate the i3admin PostgreSQL password immediately. (2) Replace the literal with <REDACTED — use OpenBao i3/postgres/admin-password> in the HTML file. (3) Run git log --all -S "?Z-EfajDpq21" -- platform/docs/03-databases-storage-guide.html to assess history exposure. ETA: ≤ 2 hours.

BLOCKER-2 · ChromaDB — no per-tenant isolation implemented (ADR-003)

Both the MCP gateway chroma.search tool and the embedding pipeline use shared, flat collection names (admissions-docs, i3-exam-corpus, onboarding-docs). No tenant-scoped collection name derivation. No where={"tenant_id": …} metadata filter. ADR-003 status is Proposed — not Accepted. This is a Kenya DPA 2019 §25 violation: cross-tenant RAG retrieval is architecturally possible on every similarity search.

Resolution: (1) Update chroma_search.py handle() to derive collection from tenant_id: collection = f"admissions_{tenant_id}" and add where={"tenant_id": {"$eq": tenant_id}}. (2) Update admissions agent to pass collection without hard-coding. (3) Update embedding pipeline to use ailab_{tenant_id}_{project} naming. (4) Accept ADR-003. ETA: ≤ 3 days.

BLOCKER-3 · Agent Registry — 2 required manifests absent; 3 use minimal schema

evalos-zuri-v1 and ford-election-agent-v1 have no manifest files. campaign-agent-v1, onboarding-agent-v1, and pmaas-campaign-agent-v1 exist but use a 7-field minimal schema (compared to the 20+ field full schema in admissions-agent-v1.yaml). The MCP gateway enforces agent permissions from the registry; incomplete manifests mean allowed_tools lists are incomplete and HC-3 cannot be machine-verified. P2-GATE-02 requires 6 ADR-002-compliant manifests.

Resolution: Author evalos-zuri-v1.yaml (state=suspended until BLOCKER-1 from VER-07 EvalOS memo resolved) and ford-election-agent-v1.yaml (state=suspended, autonomy_tier=L0). Expand the 3 thin manifests to include evaluation_spec, threat_model, approval_matrix, rollback_plan. Accept ADR-002. ETA: ≤ 2 days.

BLOCKER-4 · SEC-05 (OPEN) · OpenBao KV v2 migration not complete for 8 services

ADR-007 (Status: Proposed) identifies 9 K8s Secret → OpenBao KV v2 migrations. Only admissions is confirmed migrated (SEC-04 closed, SEC-06 closed). The remaining 8 services (engage, pmaas, evalos, ford, voice, onboarding, consent, agent-registry) still use Kubernetes Secrets with no audit log, no rotation TTL, and wide get secret RBAC. On IBM Cloud OpenShift, any service account with namespace access can read plaintext secrets. ADR-007 must be Accepted and the migration executed.

Resolution: Accept ADR-007. Execute migration in priority order: voice-secrets (SEC-03 follow-through), evalos-secrets, onboarding-secrets, engage-secrets, pmaas-secrets, ford-secrets, consent-secrets, agent-registry-secrets. Requires OpenBao agent injector running and KV paths seeded. ETA: ≤ 1 week.

Non-Blocking Warnings

The campaigns/send/route.ts code correctly hard-fails instead of falling back to raw email (the SEC-07 code fix is in place). However ADR-005 remains in Proposed status, meaning the decision has not been formally accepted by the Security Lead and DPO. Until Accepted, the control can be reverted by any PR without a governance escalation.

WARN-2 · SEC-02 (UNVERIFIED) · pmaas_setup.sql git history not audited

pmaas_setup.sql was identified as containing a plaintext DB password (EXPLORE-GATE §13). EXP-03b was never marked resolved in the dependency map. Even if the file is deleted, the credential may persist in git history. Run: git log --all --oneline -- pmaas_setup.sql; if commits exist, rotate the password and consider BFG repo cleaner for the git history.

WARN-3 · NEXTAUTH_SECRET literal in pmaas-deploy.yaml

platform/pmaas/pmaas-deploy.yaml:47: NEXTAUTH_SECRET: "5/5acuPp23ZT9+FEP8gnyE2q1HVbD1VLnjIo0TiCHLE=" is a literal value in a tracked, non-gitignored file. This is a High severity credential exposure. SEC-05 / ADR-007 migration should rotate and vault this secret before the PMaaS pod restarts.

WARN-4 · SEC-08 (PARTIAL) · chromadb version pin not confirmed in MCP gateway requirements.txt

ADR-003 AC-4 requires chromadb==0.4.24 in the service that calls ChromaDB. The MCP gateway is now the sole ChromaDB caller. Its requirements.txt version pin was not verified. An unpinned requirement will pull the latest chromadb (0.5.x), reintroducing SEC-08.

WARN-5 · ADR-006 status Proposed — Lobster Trap not applied to PMaaS + Campaign agents (code is in place)

Code-level: campaign_agent.py has guard_input() with 14-pattern Lobster Trap applied to all user-controlled fields. PMaaS briefing endpoint similarly guarded. However ADR-006 remains Proposed. Accept the ADR to formalise the control.
