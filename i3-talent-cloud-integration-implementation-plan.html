STEP 1 Create talent_db database, user, and schema on existing PostgreSQL cluster ⏱ 1 day

Creates the talent_db PostgreSQL database and all 9 Talent Graph tables on the existing Crunchy PGO cluster. Uses the same PGBouncer endpoint as every other app. No new DB infrastructure.

What gets created: candidates, certifications, skills, skill_scores, assessment_events, engagements, client_feedback, team_compositions, job_briefs, talent_edges (Talent Graph adjacency)

# 1a. Create DB + user
oc exec -n i3-data i3-postgres-primary-hffm-0 -c database -- \
  psql -U postgres -c "
    CREATE USER talent WITH PASSWORD 'talent-2026-secure';
    CREATE DATABASE talent_db OWNER talent;
    GRANT ALL PRIVILEGES ON DATABASE talent_db TO talent;
  "

# 1b. Apply schema (save platform/talent/migrations/001_init.sql first, then:)
oc cp platform/talent/migrations/001_init.sql \
  i3-data/i3-postgres-primary-hffm-0:/tmp/talent_init.sql -c database
oc exec -n i3-data i3-postgres-primary-hffm-0 -c database -- \
  psql -U postgres -d talent_db -f /tmp/talent_init.sql

Verify: SELECT tablename FROM pg_tables WHERE schemaname='public'; should return 9 tables.

Uses existing i3-postgres-pgbouncer.i3-data.svc:5432 — zero new infrastructure.

STEP 13 Add EvalOS → Talent API score webhook endpoint ⏱ 1 day

Adds a POST /api/talent-webhook route to evalos-web that fires on assessment completion. Signed with a shared secret. This is the bridge that makes EvalOS the live scoring engine for the Talent Graph.

# evalos-web: new API route (add to existing Next.js app)
# src/app/api/talent-webhook/route.ts
POST /api/talent-webhook
Body: { candidate_id, assessment_id, skill_scores[], band, langfuse_trace_id, completed_at }
Auth: X-Talent-Webhook-Secret header
Downstream: POST talent-api.i3-talent.svc.cluster.local:8080/assessments/webhook
Langfuse trace ID is stored on every call — this satisfies the governance requirement that every AI evaluation decision has an auditable trace before any placement is confirmed.

STEP 15 Launch EvalOS-as-a-Service — external client assessment access ⏱ 2 days

The fastest commercial revenue path from the specification. Packages existing EvalOS as a licensable assessment service for external clients — no new infrastructure. Two additions only:

  1. Client tenant in Keycloak — a new group or sub-realm per paying client, or role-based isolation in the existing i3 realm for MVP
  2. Assessment invite API — Talent API endpoint POST /assessments/invite that creates a time-limited Keycloak registration link for an external candidate → sends via Engage email → candidate logs in, completes EvalOS, score posts back to client dashboard in talent-web
# Invite flow (entire flow uses existing services)
1. Client creates job brief in talent-web → selects "EvalOS screening"
2. Talent API POSTs to Keycloak: create temp user with talent-candidate role
3. Talent API POSTs to Engage: send invite email with login link
4. Candidate logs in → completes EvalOS assessment (existing evalos.i3technologies.co.ke)
5. EvalOS fires webhook → Talent API updates candidate score
6. Client views scored shortlist in talent-web /shortlist

STEP 18 Production hardening — GDPR/DPA compliance, data encryption, SLA monitoring ⏱ 3 days

Required before external client data enters the system. Three additions to the Talent API:

  • Right-to-erasure endpoint DELETE /candidates/:id — hard-deletes all PII from PostgreSQL and SeaweedFS, publishes talent-placements Kafka tombstone event
  • Field-level encryption — PII fields (phone, NDA details) encrypted at rest using per-candidate keys from OpenBao (vault transit engine)
  • Consent tracking — candidates.consent_given_at and candidates.consent_version columns; consent required before any EvalOS assessment is triggered
Kenya Data Protection Act 2019: Any personal data of Kenyan residents stored on the platform is subject to KDPA. The right-to-erasure endpoint and consent tracking are legally required before commercial launch, not optional.
