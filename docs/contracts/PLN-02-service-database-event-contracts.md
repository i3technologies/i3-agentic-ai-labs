## CONTRACT-1: Consent Service

### Context

The consent service is a **new bounded-context service** (namespace `i3-consent`).  
It does not yet have application code — only the circuit-breaker client exists at
`platform/consent/circuit_breaker.py`. Callers already hard-code the in-cluster DNS
`http://consent-service.i3-consent.svc.cluster.local:8000`. This contract defines
the complete server side.

**DPA 2019 §25 mandate**: default-deny — absence of a consent record MUST resolve to `allowed=false`.
The circuit-breaker in `circuit_breaker.py` enforces fail-closed on network errors; this contract
must enforce default-deny at the data layer too.

---

### A. REST API

#### Base URL

```
https://consent.i3technologies.co.ke   (external)
http://consent-service.i3-consent.svc.cluster.local:8000   (in-cluster)
```

#### Authentication & Authorization

| Layer | Mechanism |
|-------|-----------|
| External ingress | Kong Gateway + Keycloak Bearer JWT (RS256). `tenant_id` from JWT claim. |
| In-cluster service-to-service | mTLS (Istio sidecar). Caller sets `X-Tenant-Id` header. JWT not required from trusted namespaces. |
| Write endpoints | Require `realm_access.roles` containing `consent:write` |
| Read endpoints | Require `realm_access.roles` containing `consent:read` or service identity |

#### Standard Headers (all requests)

| Header | Type | Required | Description |
|--------|------|----------|-------------|
| `Authorization` | `Bearer <jwt>` | External only | Keycloak RS256 JWT |
| `X-Tenant-Id` | UUID | Yes | Tenant scoping (HC-4). Validated against JWT claim on external calls. |
| `X-Correlation-Id` | UUID | Recommended | Propagated to all audit log entries. Generated by service if absent. |
| `Idempotency-Key` | UUID | POST/PUT only | Client-generated UUIDv7. Duplicate requests within 24 h return the cached response. |

---

#### Endpoints

##### `GET /consent/{subject_id_hash}`

Check current consent status. This is the **hot path** called by the circuit-breaker.

**Path parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `subject_id_hash` | string (64 hex chars) | HMAC-SHA256(MEMBER_HMAC_SECRET, identifier). HC-6 — raw NID/phone MUST NOT appear here. |

**Query parameters**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `channel` | enum | Yes | `email` \| `sms` \| `whatsapp` \| `voice` \| `enrollment` \| `marketing` |
| `purpose` | enum | Yes | `marketing` \| `education` \| `enrollment` \| `research` |
| `tenant_id` | UUID | Yes | Must match `X-Tenant-Id` |

**Response 200**
```json
{
  "allowed":           true,
  "subject_id_hash":   "a3f1...",
  "channel":           "email",
  "purpose":           "marketing",
  "tenant_id":         "00000000-0000-0000-0000-000000000001",
  "recorded_at":       "2025-07-01T09:00:00Z",
  "expires_at":        null,
  "consent_record_id": "019236ab-0000-7000-8000-000000000001"
}
```

**Response 404** — no record found → **must** be treated as `allowed=false` by caller
```json
{
  "allowed":  false,
  "detail":   "No consent record found (default-deny, DPA 2019 §25)",
  "subject_id_hash": "a3f1...",
  "channel":  "email",
  "purpose":  "marketing"
}
```

**Status codes**

| Code | Condition |
|------|-----------|
| 200 | Record found, `allowed` reflects the stored value |
| 404 | No record → treat as denied |
| 400 | Malformed `subject_id_hash` or unknown enum |
| 401 | Missing/invalid JWT (external) |
| 403 | `X-Tenant-Id` mismatch |
| 429 | Rate-limit exceeded (100 req/s per tenant) |

---

##### `POST /consent`

Create or refresh a consent record (explicit opt-in).

**Request body**
```json
{
  "subject_id_hash": "a3f1...",
  "channel":         "email",
  "purpose":         "marketing",
  "tenant_id":       "00000000-0000-0000-0000-000000000001",
  "consented":       true,
  "source":          "web-form",
  "expires_at":      null
}
```

| Field | Type | Required | Constraint |
|-------|------|----------|------------|
| `subject_id_hash` | string | Yes | 64-char hex (HMAC-SHA256) |
| `channel` | enum | Yes | See allowed values above |
| `purpose` | enum | Yes | See allowed values above |
| `tenant_id` | UUID | Yes | HC-4: must match `X-Tenant-Id` |
| `consented` | boolean | Yes | `true` = opt-in, `false` = opt-out/revoke |
| `source` | string | Yes | max 100 chars; free text audit trail |
| `expires_at` | ISO8601 \| null | No | null = perpetual; GDPR-advised max 2 years |

**Response 201** (idempotent on repeat `Idempotency-Key`)
```json
{
  "consent_record_id": "019236ab-0000-7000-8000-000000000001",
  "subject_id_hash":   "a3f1...",
  "channel":           "email",
  "purpose":           "marketing",
  "consented":         true,
  "recorded_at":       "2025-07-01T09:00:00Z"
}
```

| Code | Condition |
|------|-----------|
| 201 | Created or idempotent repeat |
| 400 | Validation failure |
| 401/403 | Auth failure |
| 409 | Duplicate (non-idempotent second write without `Idempotency-Key`) |

---

##### `DELETE /consent/{subject_id_hash}`

Revoke all consent records for a subject (right to erasure / DPA §35).  
Logically deletes; preserves audit trail in `consent_audit_log`.

**Query parameters**: `tenant_id` (required), `channel` (optional — omit to revoke all channels)

**Response 204** — no body

```json
{
  "status":   "ok",
  "db":       "healthy",
  "breaker":  "CLOSED"
}
```

### B. PostgreSQL 16 Schema

> All `CREATE TABLE` statements below have been reviewed against the
> `audit_sql_ast` checklist: UUIDv7 PKs, `tenant_id UUID NOT NULL`,
> composite index on `(tenant_id, created_at DESC)`, RLS enabled, soft-delete where applicable.

```sql
-- ── Extension required ──────────────────────────────────────────────────────
-- UUIDv7 generation. Use pg_uuidv7 extension (available on Crunchy Postgres).
CREATE EXTENSION IF NOT EXISTS pg_uuidv7;

-- ── Table: consent_records ──────────────────────────────────────────────────
CREATE TABLE consent_records (
    id                UUID        NOT NULL DEFAULT uuidv7()       PRIMARY KEY,
    tenant_id         UUID        NOT NULL,                        -- HC-4
    subject_id_hash   VARCHAR(64) NOT NULL,                        -- HC-6: HMAC-SHA256 hex
    channel           VARCHAR(20) NOT NULL
                        CHECK (channel IN ('email','sms','whatsapp','voice','enrollment','marketing')),
    purpose           VARCHAR(20) NOT NULL
                        CHECK (purpose IN ('marketing','education','enrollment','research')),
    consented         BOOLEAN     NOT NULL DEFAULT FALSE,          -- DPA §25 default-deny
    source            VARCHAR(100) NOT NULL,
    expires_at        TIMESTAMPTZ,                                 -- NULL = perpetual
    idempotency_key   UUID,
    created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at        TIMESTAMPTZ,                                 -- soft-delete (right to erasure)
    created_by        TEXT        NOT NULL DEFAULT 'system',
    updated_by        TEXT        NOT NULL DEFAULT 'system',

    CONSTRAINT uq_consent_subject_channel_purpose
        UNIQUE (tenant_id, subject_id_hash, channel, purpose)
        WHERE deleted_at IS NULL,

    CONSTRAINT uq_idempotency_key
        UNIQUE (idempotency_key)
        WHERE idempotency_key IS NOT NULL
);

-- Composite index for hot-path GET /consent/{hash} query
CREATE INDEX idx_consent_tenant_subject
    ON consent_records (tenant_id, subject_id_hash)
    WHERE deleted_at IS NULL;

-- Composite index for audit/admin queries ordered by recency
CREATE INDEX idx_consent_tenant_created
    ON consent_records (tenant_id, created_at DESC);

-- Partial index: active records only (eliminates deleted_at IS NULL scan)
CREATE INDEX idx_consent_active
    ON consent_records (tenant_id, subject_id_hash, channel, purpose)
    WHERE deleted_at IS NULL AND consented = TRUE;

-- Expiry sweep support
CREATE INDEX idx_consent_expires
    ON consent_records (expires_at)
    WHERE expires_at IS NOT NULL AND deleted_at IS NULL;

ALTER TABLE consent_records ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON consent_records
    USING (tenant_id = current_setting('app.tenant_id')::UUID);

-- ── Table: consent_audit_log ────────────────────────────────────────────────
-- Immutable append-only audit log. Never updated or soft-deleted.
CREATE TABLE consent_audit_log (
    id               UUID        NOT NULL DEFAULT uuidv7()        PRIMARY KEY,
    tenant_id        UUID        NOT NULL,                         -- HC-4
    consent_record_id UUID,                                        -- FK nullable (pre-creation events)
    subject_id_hash  VARCHAR(64) NOT NULL,
    action           VARCHAR(20) NOT NULL
                       CHECK (action IN ('created','updated','revoked','expired','queried')),
    channel          VARCHAR(20) NOT NULL,
    purpose          VARCHAR(20) NOT NULL,
    actor            TEXT        NOT NULL,                         -- service name or user sub
    correlation_id   UUID,
    payload_snapshot JSONB       NOT NULL DEFAULT '{}',            -- safe subset, no raw PII
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_tenant_created
    ON consent_audit_log (tenant_id, created_at DESC);

CREATE INDEX idx_audit_subject
    ON consent_audit_log (tenant_id, subject_id_hash);

ALTER TABLE consent_audit_log ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON consent_audit_log
    USING (tenant_id = current_setting('app.tenant_id')::UUID);

-- ── Table: idempotency_keys ─────────────────────────────────────────────────
-- Deduplicate POST /consent within 24 h TTL.
CREATE TABLE idempotency_keys (
    key              UUID        NOT NULL PRIMARY KEY,
    tenant_id        UUID        NOT NULL,
    response_body    JSONB       NOT NULL,
    status_code      SMALLINT    NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at       TIMESTAMPTZ NOT NULL DEFAULT NOW() + INTERVAL '24 hours'
);

CREATE INDEX idx_idempotency_expires
    ON idempotency_keys (expires_at);

ALTER TABLE idempotency_keys ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON idempotency_keys
    USING (tenant_id = current_setting('app.tenant_id')::UUID);
```

**`audit_sql_ast` findings & resolutions**

| Finding | Resolution |
|---------|------------|
| `tenant_id UUID NOT NULL` absent | Added to all three tables ✅ |
| No RLS on any table | `ENABLE ROW LEVEL SECURITY` + `CREATE POLICY tenant_isolation` on all three ✅ |
| No composite index on `(tenant_id, created_at DESC)` | `idx_consent_tenant_created`, `idx_audit_tenant_created` ✅ |
| PK not UUIDv7 | `DEFAULT uuidv7()` on all PKs ✅ |
| No soft-delete on `consent_records` | `deleted_at TIMESTAMPTZ` column + partial unique constraint excludes deleted rows ✅ |
| No idempotency key table | `idempotency_keys` table added ✅ |
| No audit trail | `consent_audit_log` is immutable append-only ✅ |

### C. Event Contract

Every state change on `consent_records` MUST emit a CloudEvent to the `consent.events` topic.

**Topic**: `consent.events`  
**Partition key**: `tenantid` (routes all events for a tenant to the same partition)

#### `i3.consent.record.created`
```json
{
  "specversion":     "1.0",
  "id":              "019236ab-0000-7000-8000-000000000001",
  "source":          "i3/consent-service",
  "type":            "i3.consent.record.created",
  "datacontenttype": "application/json",
  "time":            "2025-07-01T09:00:00Z",
  "tenantid":        "00000000-0000-0000-0000-000000000001",
  "subject":         "consent-record/019236ab-0000-7000-8000-000000000001",
  "data": {
    "consent_record_id": "019236ab-0000-7000-8000-000000000001",

    "source":            "web-form",
    "correlation_id":    "uuid-of-originating-request"

```

#### `i3.consent.record.revoked`
Same envelope; `data.consented = false`. `type = "i3.consent.record.revoked"`.

#### `i3.consent.record.expired`
Emitted by the expiry-sweep job. `type = "i3.consent.record.expired"`.

### D. Redis Contract

The consent service uses Redis **only** for idempotency key short-circuit (24 h window) to avoid
hot-path DB reads on duplicate POST requests.

| Key | Format | TTL | Serialization |
|-----|--------|-----|---------------|
| `consent:idem:{tenant_id}:{idempotency_key}` | `{status_code}:{json_body}` | 86 400 s (24 h) | UTF-8 string |

**Tenant scoping**: `tenant_id` is embedded in the key prefix — a tenant cannot access another
tenant's idempotency record.

**Invalidation**: None. Keys expire automatically. The DB `idempotency_keys` table is the
durable record; Redis is the fast-path cache.

---

### F. Security Model

| Control | Implementation |
|---------|----------------|
| **Default-deny** | 404 response treated as `allowed=false`; DB `DEFAULT FALSE` |
| **No raw PII** | `subject_id_hash` is always HMAC-SHA256(MEMBER_HMAC_SECRET, identifier) per HC-6 |
| **RLS** | All tables have `tenant_isolation` policy; `app.tenant_id` set per request |
| **Circuit-breaker** | Callers use `platform/consent/circuit_breaker.py` — fail-closed in OPEN state |
| **mTLS** | Istio sidecar on `i3-consent` namespace |
| **Write authorization** | `consent:write` Keycloak role required |
| **Audit trail** | All mutations written to `consent_audit_log` before returning response |
| **DPA §25** | Absence of record = denied; `consented` column defaults to `FALSE` |

### Context

`_build_cloud_event()` helper but contains **no dedicated producer for the four inbound topics**.
Producers are upstream callers (campaign agent, Engage web API). This contract defines the

### C. Event Contracts (Nine-Field Envelope)

All four topics use the 9-field i3 CloudEvent envelope. `tenantid` is UUID NOT NULL (HC-4).
Partition key for all topics: `tenantid` value — ensures all events for a tenant land in the
same partition for ordered processing.

### B. PostgreSQL 16 Schema (Engage — producer-side send_jobs tracking)

```sql
CREATE EXTENSION IF NOT EXISTS pg_uuidv7;

-- ── Table: email_send_jobs ──────────────────────────────────────────────────
-- Tracks each producer-initiated send job before the CloudEvent is emitted.
CREATE TABLE email_send_jobs (

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

CREATE INDEX idx_send_jobs_tenant_created
    ON email_send_jobs (tenant_id, created_at DESC);

CREATE INDEX idx_send_jobs_status
    ON email_send_jobs (tenant_id, status)
    WHERE status NOT IN ('complete','failed');
```

## CONTRACT-4: Onboarding Agent Redis Plan Store

### Context

`onboarding-agent/src/render/taskSync.ts` and `onboarding-agent/src/orchestrator/planner.ts`
already implement the Redis plan store with key schema `sync:{pendingId}` and TTL 300 s.
This contract formalises the key naming, tenant scoping, serialization, and TTL strategy —
and adds the missing `plan:` namespace for the generated `RampUpPlan` objects.

---

### A. REST API

The HTTP API is defined in the onboarding agent's Express server. The Redis contract
underpins the two-stage confirmation workflow:

| Endpoint | Redis Operation |
|----------|----------------|
| `POST /api/onboarding/plan` | Write `plan:{tenantId}:{sessionId}` (TTL 1800 s) |
| `POST /api/onboarding/sync/prepare` | Write `sync:{pendingId}` (TTL 300 s) |
| `POST /api/onboarding/sync/confirm/:pendingId` | Read + DEL `sync:{pendingId}` |
| `DELETE /api/onboarding/sync/:pendingId` | DEL `sync:{pendingId}` |
| `GET /healthz` | Read `pendingSyncCount()` via `KEYS sync:*` |

**Headers**: `X-Tenant-Id` (UUID, required), `X-Correlation-Id` (UUID, recommended).
**Auth**: Keycloak Bearer JWT — `tenant_id` extracted from `sub` + `tenant_id` JWT claim.

---

### D. Redis Contract

#### Namespace Matrix

| Key pattern | Stores | TTL | Serialization | Tenant scoping |
|-------------|--------|-----|---------------|----------------|
| `onboarding:{tenantId}:plan:{sessionId}` | `RampUpPlan` JSON | 1 800 s (30 min) | `JSON.stringify` | `tenantId` in key prefix |
| `onboarding:{tenantId}:sync:{pendingId}` | `PendingSync` JSON | 300 s (5 min) | `JSON.stringify` | `tenantId` in key prefix |

> **Current code gap**: `taskSync.ts` uses `sync:{pendingId}` without `tenantId` in the prefix.
> This contract upgrades the schema to `onboarding:{tenantId}:sync:{pendingId}` to enforce
> tenant isolation. The `plan:` namespace is new and not yet implemented.

#### `onboarding:{tenantId}:plan:{sessionId}` — `RampUpPlan`

```typescript
interface RampUpPlan {
  schemaVersion:        "1.0";
  generatedAt:          string;    // ISO8601
  role:                 string;
  architecturalSummary: ArchitecturalSummary;
  tasks:                RampUpTask[];
  totalVerified:        number;
  totalUnverified:      number;
  staleDocWarnings:     string[];
}
```

**Set**: `SET onboarding:{tenantId}:plan:{sessionId} <JSON> EX 1800`  
**Get**: `GET onboarding:{tenantId}:plan:{sessionId}` → parse JSON  
**Delete**: Implicit TTL expiry. Explicit DEL on user plan dismissal.

---

#### `onboarding:{tenantId}:sync:{pendingId}` — `PendingSync`

```typescript
interface PendingSync {
  planId:    string;
  tasks:     RampUpTask[];
  role:      string;
  userId:    string;    // Keycloak sub — confirmation must match
  tenantId:  string;    // Added: tenant isolation in payload as well as key
  expiresAt: number;    // epoch ms — informational; TTL enforced by Redis EX
}
```

**Set**: `SET onboarding:{tenantId}:sync:{pendingId} <JSON> EX 300`  
**Get**: `GET onboarding:{tenantId}:sync:{pendingId}` → parse JSON, verify `userId` match  
**Delete**: `DEL onboarding:{tenantId}:sync:{pendingId}` — called immediately before confirming (prevents double-fire)

---

#### Key Design Rationale

| Decision | Reason |
|----------|--------|
| `tenantId` in prefix | Prevents a tenant from reading or cancelling another tenant's pending sync — even if `pendingId` is guessed |
| DEL before confirm | Token consumption pattern — deleting before executing prevents replay from a concurrent request |
| `userId` in payload | Ensures the confirming user is the same user who initiated the prepare stage |
| `expiresAt` in payload | Client-side UX (countdown display) without needing a Redis TTL query |

---

#### Invalidation Rules

| Trigger | Action |
|---------|--------|
| TTL expiry (300 s / 1800 s) | Automatic Redis eviction |
| User clicks "Dismiss" | `DEL onboarding:{tenantId}:sync:{pendingId}` |
| Confirm successful | `DEL` before executing write |
| Plan regenerated | `SET` with new `sessionId` (old key remains until TTL) |
| User logout | `DEL onboarding:{tenantId}:sync:*` and `onboarding:{tenantId}:plan:*` patterns (use `SCAN` not `KEYS` in production) |

---

#### Redis Client Configuration (TypeScript)

```typescript
// server.ts
import { createClient } from 'redis';

const redis = createClient({
  url:      process.env.REDIS_URL,       // redis://redis.i3-data.svc.cluster.local:6379/1
  password: process.env.REDIS_PASSWORD,  // from OpenBao i3/onboarding/redis-password
  socket: { tls: true, rejectUnauthorized: true },
  database: 1,   // Dedicated DB index — separates onboarding from other services
});
```

> **Current code note**: `taskSync.ts` stores `sync:{pendingId}` in the default Redis database.
> This contract mandates DB index 1 (`database: 1`) to isolate onboarding keys.

---

### F. Security Model

| Control | Implementation |
|---------|----------------|
| **Tenant isolation** | `tenantId` embedded in all Redis key prefixes |
| **User binding** | `userId` in `PendingSync` payload — mismatch returns `403`-equivalent error |
| **Token consumption** | `DEL` before executing confirm — prevents double-fire and replay |
| **TTL** | 300 s for pending syncs; 1800 s for plans — data minimisation per DPA |
| **No raw PII in Redis** | `RampUpPlan` and `PendingSync` contain only task metadata and Keycloak `sub` |
| **TLS** | `rejectUnauthorized: true` on Redis TLS socket (architecture-standards.md §TypeScript) |
| **SCAN not KEYS** | Bulk invalidation uses `SCAN` with cursor to avoid blocking the Redis event loop |
