DEMO SCRIPT — 4 Beats (~8 minutes total)

Each beat is a talking point + live command. Narrate as you type. Never rush — slow, deliberate typing shows confidence.

1
Set the Scene — The Problem
~1 min · no commands

Say this while showing the GitHub repo or the README:

"Every engineering team has the same problem — a new hire joins, the codebase has 150 files across 12 namespaces, the README is six months out of date, and the team lead spends two full days hand-holding them through setup.

We built an AI agent that reads the actual live codebase, fires three AI subagents in parallel to analyse it, then generates a verified, role-specific 5-day ramp-up plan — in a single API call. The key word is verified. It doesn't just generate tasks — it checks that every file path it references actually exists in the repository."

Point at the architecture diagram in the README if showing on screen.

2
Live API Call — Generate a Plan
~2 min · Terminal 3

Say: "Let me show you what this looks like. I'm going to hire a new Platform Engineer right now."

# In Terminal 3 — type this live
$r = Invoke-RestMethod http://localhost:3000/api/onboarding/plan `
  -Method POST -ContentType "application/json" `
  -Body '{"role":"platform_engineer"}'

# Show the summary numbers immediately
Write-Host "Tasks: $($r.plan.tasks.Count)  Verified: $($r.totalVerified)  Stale: $($r.totalUnverified)"

Expected output:

Tasks: 9  Verified: 8  Stale: 1

Say: "One API call. Three AI subagents ran in parallel — infra scanner, AI lab scanner, backend scanner — each pulling context from the codebase. In under three seconds we have a structured JSON plan with 9 tasks, 8 verified, and — here's the key — one stale doc detection."

# Show the full task table
$r.plan.tasks | Format-Table day, verified, priority, title -Wrap

Point out: The columns — Day 1 tasks are HIGH priority, the table shows True/False in the verified column, and there's one False row.

THE KEY DEMO MOMENT — Live Stale Doc Detection
~2 min · Terminal 3
★ This is the moment that wins the hackathon

The agent catches its own stale claim — live, using the real Kubernetes API

Most "AI" demos are wrappers that generate plausible-sounding text. This proves the agent is grounded in reality — it checks live infrastructure.

# Show ONLY the stale tasks — this is the demo highlight
$r.plan.tasks | Where-Object { -not $_.verified } | Format-List title, verificationNote

"Look at that. Our own platform documentation says RHOAI — Red Hat OpenShift AI — is available. The agent didn't just read the docs and believe them. It called the live Kubernetes API, checked whether the namespace actually exists in our cluster, confirmed it doesn't — because it's a Month 3 rollout — and automatically flagged that task with this exact prefix: 'Needs verification — referenced path not found — likely stale doc.'

That's not a simulation. That's the agent catching a real stale documentation claim in real time."

ANTICIPATED JUDGE QUESTIONS

QuestionAnswer
"How is this different from just asking ChatGPT to write an onboarding plan?" ChatGPT makes up file paths. Ours calls existsSync() on every referenced path and calls the live Kubernetes API to check namespace availability. The stale-doc prefix — "Needs verification: ... referenced path not found" — is generated in real time from real infrastructure state, not from language model intuition.
"What model are you using?" Three tiers: granite-nano (IBM, Tier 3) for embeddings, mistral-nemo (Tier 2) for all three parallel subagent scans, and granite-heavy (IBM watsonx.ai, Tier 1) called exactly once per plan for final synthesis. This conserves our $14k IBM Cloud credit budget — 90% of calls are local Ollama.
"What is the confidence gate?" The planner applies a 0.65 threshold — any task the model assigns below 65% confidence is automatically dropped from the plan before it reaches the new hire. It's the same gate used in our admissions agent, calibrated against RAGAS evaluation scores.
"How do you measure quality?" RAGAS LLM-as-judge evaluation in platform/testing/testing.py --ragas-onboarding. Two thresholds: Faithfulness ≥ 0.80 (the plan doesn't hallucinate file paths) and Answer Relevancy ≥ 0.75 (the tasks are actually relevant to the role). These run as part of our CI via make test-onboarding.
"Is this production-ready?" The OpenShift manifest is live in our ArgoCD wave 7. HPA scales 1–3 replicas. Secrets injected from OpenBao KV v2 — zero secrets in code or git. Keycloak RS256 JWT auth on every endpoint. Tekton CI runs typecheck + buildah + trivy on every push. The only thing keeping it from full prod is the RHOAI Month 3 rollout — which, as you just saw, the agent correctly identifies as a stale doc.
"Why Node.js instead of Python?" Same runtime as the rest of the team's tooling. The Python admissions agent already covers the Python surface area — no value in duplicating it. One codebase, one runtime, one deploy target for a 48-hour hackathon window.
"What's the Lobster Trap?" Our prompt injection firewall — 12 regex patterns that block classic attacks (ignore previous instructions, DAN mode, SQL injection, HTML injection, exfiltrate) before any user input reaches an LLM. Named after our platform security policy.
