Fixes Applied This Session

✅ Fix #1 — Voice STT & TTS: NetworkPolicy Patched
Root cause: voice-ingress NetworkPolicy only allowed traffic from 5 internal namespaces — openshift-ingress (the router) was not included, causing all external HTTP to time out at the LB.
Fix: Added namespaceSelector: kubernetes.io/metadata.name: openshift-ingress to voice-ingress NP in i3-voice.
File: platform/scripts/voice-ingress-np-patch.yaml applied via oc apply.
Result: stt.i3technologies.co.ke/v1/health → 200   tts.i3technologies.co.ke/v1/health → 200
✅ Fix #2 — pgBackRest Backup Failures: Port 8432 Unblocked
Root cause: allow-postgres-internal NetworkPolicy only permitted ports 5432 and 8008 between cluster pods. The pgBackRest TLS server binds to port 8432 on primary pods — this port was blocked, causing all scheduled backup jobs to fail with "timeout connecting to … :8432" since Sep 14 06:00 UTC.
Fix: Added port: 8432 to allow-postgres-internal NP in i3-data.
File: platform/scripts/pg-internal-np-patch.json applied via oc patch.
Verified: Manual diff backup triggered from primary pod — completed successfully at 2026-09-16 02:30:46 UTC. Stanza status: ok. Scheduled jobs will succeed at next run (06:00 UTC).
✅ Fix #3 — Admissions & Onboarding: Routes Pointed to /health
Root cause: Both agent pods expose only /health (and API sub-paths) — no GET / handler exists. Routes had no path set so the LB served / → 404.
Fix: Patched admissions-public (i3-admissions) and onboarding-agent (i3-onboarding) routes to set spec.path: /health via oc patch --type=merge.
Result: admissions.i3technologies.co.ke/health → 200   onboarding.i3technologies.co.ke/health → 200
