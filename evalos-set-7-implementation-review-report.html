Key Findings

🔴 Critical: draw_spec not wired into the deployed start/route.ts

The exam's draw_spec column is correctly seeded in Migration 012, but the live Next.js route at platform/evalos/web/src/app/api/exam/[examId]/start/route.ts still performs a flat WHERE set_number = $1 ORDER BY question_number query. The rotating-bank feature — the central deliverable of Set 7 — will not function until this route is updated to read draw_spec and perform per-domain random draws via ORDER BY RANDOM() LIMIT $count. Reference implementation exists in platform/evalos/nextjs/exam-engine.ts and must be ported to the deployed route.

🟡 Partial: HC-4 tenant_id not filtering the question SELECT query

The RLS session variable is correctly set and the quiz_attempts INSERT includes tenant_id, but the question fetch query (lines 201–207) has no tenant_id predicate. The plan's required fix — AND (tenant_id = $tenantId OR tenant_id IS NULL) — was not applied. This creates a cross-tenant question visibility risk that must be resolved before Set 7 is published to production.

🟢 Retake Window Enforcement: Fully Implemented

Migration 012 adds retake_window_hours INT to exams. The start/route.ts enforces it with a deadline check (lines 137–162). Set 7 is configured at 48 hours. This was not in the original plan's 5 core changes but is a valuable addition that strengthens exam integrity.

🟢 Integrity Scoring + Device Fingerprint: Fully Implemented

Device fingerprint is captured at session start, drift is detected on resume, and computeIntegrityScores() runs at submit time to produce trust_score, requires_review, identity_score, and behavior_score — all persisted to quiz_attempts and dispatched in the n8n webhook.

🟢 60-Question Set 7 Bank: Fully Seeded

All 60 questions across 7 domains (Q1–Q60) are seeded in Migration 012 with correct domain mappings, MC/MR types, options as JSONB arrays, correct_answers as ARRAY, and full explanations. Questions cover all C1000-207 domains per IBM exam weighting.
