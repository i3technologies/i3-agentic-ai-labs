6 · Issues & Required Actions

🔴 ISSUE-P1S3-01 · engage-web build broken (next-pwa babel transitive dep)

Severity: Critical — CI/CD pipeline cannot produce a deployable image

Root cause: next-pwa@5.6.0 pins an old rollup-plugin-terser which requires @babel/helper-validator-identifier — not hoisted by npm v10 in Node 22 environments.

  • Fix: replace next-pwa@5.6.0 with @ducanh2912/next-pwa@^10 in platform/engage/web/package.json (and same in pmaas-web)
  • Alternatively: add a resolutions / overrides block to force a compatible @babel/helper-validator-identifier

🔴 ISSUE-P1S3-02 · pmaas-web: missing RLS SET LOCAL on campaign queries

Severity: Critical — HC-4 tenant isolation violated

Location: platform/pmaas/web/src/app/api/campaigns/route.ts lines 17–29

All three query calls (pool.query for GET/POST/PATCH) execute without SET LOCAL app.tenant_id. A single shared DB connection could cross-contaminate tenant rows. Fix: wrap each handler in pool.connect() and issue SET LOCAL app.tenant_id = $1 using the session's tenant_id.

🟡 ISSUE-P1S3-03 · engage-web & evalos-web: no "lint" script in engage-web package.json

Severity: Medium — CI lint gate cannot run

Add "lint": "next lint" to the scripts block of platform/engage/web/package.json (same as evalos-web and pmaas-web).

🟡 ISSUE-P1S3-04 · X-Tenant-Id header not forwarded in client-side fetch() calls

Severity: Medium — cross-origin tenant propagation missing

All three frontends (engage, evalos, pmaas) make client-side fetch('/api/...') calls with no explicit X-Tenant-Id header. Tenant context is currently carried only via the NextAuth session cookie to server actions. For external API consumers or future service-to-service calls through Kong, the header must be explicitly set.

  • Create a shared apiFetch(url, opts, session) wrapper that injects Authorization: Bearer <accessToken> and X-Tenant-Id: <tenant_id>
  • Required for Kong consumer-level rate limiting by tenant and for backend tenant_id validation on non-Next.js services

🟡 ISSUE-P1S3-05 · pmaas-web contains chromadb dependency (SC-P2-04-A violation)

Severity: Medium — P2-04 sensor check fails; forbidden direct vector DB coupling

Location: platform/pmaas/web/package.json line 18: "chromadb": "^1.8.1"

Per SC-P2-04-A the chromadb direct import must be removed. Vector search must route through the MCP Gateway chroma_search tool.

🟡 ISSUE-P1S3-06 · ASYNC_CAMPAIGN_SEND feature flag undocumented; default-off means P3-02 contract not active

Severity: Medium — the P3-02 async contract (HTTP 202) is only reachable when ASYNC_CAMPAIGN_SEND=true

The env var must be set in platform/engage/web Kubernetes Deployment manifest and documented in the environment run-book. Verify it is set in the ConfigMap / Secret before P3-02 is marked complete.

🟡 ISSUE-P1S3-07 · next@14.2.5 has a published security vulnerability

Severity: Medium security — npm warns of known CVE

All three frontends pin next@14.2.5. npm audit warns: "This version has a security vulnerability. Please upgrade." Evaluate upgrading to a patched 14.x release or Next.js 15.x before production rollout.
