5. How to Create Users

Method A — Keycloak Admin Console (GUI)

1. Log in to Keycloak Admin Console
Navigate to https://sso.i3.tech/admin
Username: from keycloak-admin-secret (set during deploy)
Password: from the same secret

First time only — retrieve the initial admin password: 
oc get secret keycloak-admin-secret -n i3-auth \
  -o jsonpath='{.data.password}' | base64 -d
2. Switch to the i3 realm
In the top-left dropdown, select i3 (not master).
All students, instructors, and admins must be created in the i3 realm.
3. Create a single user
  1. Left sidebar → Users → Add user
  2. Fill: Username (e.g. alice.mwangi), Email, First name, Last name
  3. Toggle Email verified → On
  4. Click Create
  5. Go to Credentials tab → Set Password → uncheck Temporary → Save password
  6. Go to Role mappings tab → Assign role → filter by realm → pick student / instructor / admin

Method B — Keycloak CLI (bulk import, scripted)

Bulk-create students from a CSV via kcadm.sh
# Run inside the Keycloak pod
KC_POD=$(oc get pods -n i3-auth -l app=keycloak -o jsonpath='{.items[0].metadata.name}')
oc exec -n i3-auth $KC_POD -- /opt/keycloak/bin/kcadm.sh \
  config credentials \
  --server https://localhost:8443 \
  --realm master \
  --user admin \
  --password "$KEYCLOAK_ADMIN_PASSWORD"

# Create one user
oc exec -n i3-auth $KC_POD -- /opt/keycloak/bin/kcadm.sh \
  create users -r i3 \
  -s username=alice.mwangi \
  -s email=alice@example.com \
  -s firstName=Alice \
  -s lastName=Mwangi \
  -s enabled=true \
  -s emailVerified=true

# Set password
USER_ID=$(oc exec -n i3-auth $KC_POD -- \
  /opt/keycloak/bin/kcadm.sh get users -r i3 -q username=alice.mwangi \
  | grep '"id"' | head -1 | cut -d'"' -f4)

oc exec -n i3-auth $KC_POD -- /opt/keycloak/bin/kcadm.sh \
  set-password -r i3 --username alice.mwangi --new-password "Temp@1234!"

# Assign role
oc exec -n i3-auth $KC_POD -- /opt/keycloak/bin/kcadm.sh \
  add-roles -r i3 --uusername alice.mwangi --rolename student

Method C — Provision via Auto-Enrolment (n8n → Keycloak)

When a student passes EvalOS, the enrolment queue triggers the n8n workflow which can call Keycloak's REST API to auto-create the user. This is the M5 automated path — no manual steps needed after EvalOS PASS.

Method D — AI Lab Cohort Provisioning (Makefile)

Provision a cohort namespace + RBAC for students
# Creates ai-lab-cohort-01 namespace with RBAC for 3 students
make provision-cohort COHORT=1 STUDENTS=alice.mwangi,bob.otieno,carol.kamau GPU_QUOTA=0
Students identified here must also exist as Keycloak users (Methods A/B above). Their Keycloak username becomes their RBAC subject in the format username@i3.tech.

9. Password Policy (Keycloak Enforced)

All user passwords in the i3 realm must meet this policy (configured in keycloak-realm.yaml):

  • Minimum 12 characters
  • At least 1 uppercase letter
  • At least 1 lowercase letter
  • At least 1 digit
  • At least 1 special character
  • Brute-force protection: 5 failed attempts → account temporarily locked
  • Password reset: allowed (email-based)
  • Token lifetime: 1 hour access token / 10 hour SSO session

Example valid password: AcademyAI@2026!
