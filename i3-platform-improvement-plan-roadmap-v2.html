Sourced from i3_AI_Lab_P0_Technical_Build_Spec.md — immediate must-dos to make the current platform production-grade.

B2 — Metering, Quotas & Billing (Weeks 1–4)

LiteLLM natively writes spend to Postgres. Implement the billing schema and nightly ETL:

  • Create billing schema in PostgreSQL: customers → projects → api_keys → monthly_usage tables
  • Issue per-project LiteLLM keys (retire master key sk-i3-internal for client use)
  • Set per-key max_budget, RPM limits, soft alerts at 50%/80%/95%
  • Nightly ETL job (n8n workflow): aggregate spend_logs → monthly_usage → CSV/PDF invoice per customer
  • Grafana dashboard: month-to-date spend vs budget per customer

Estimate: 1–2 engineers × 2–3 weeks

B4-MVP — Multi-Tenancy, RBAC & Audit Logging (Weeks 3–6)

  • OpenShift namespace per enterprise customer: cust-<slug>
  • Three roles per namespace: admin / developer / viewer — mapped from Keycloak groups
  • Append-only object-store audit bucket (WORM, 7-year retention) for all API + platform events
  • Retire master key for interactive use — keep as break-glass service account only
  • JupyterHub: kubespawner places user pods in customer namespace from SSO group claims

Estimate: 1–2 engineers × 2–3 weeks

B5-MVP — Model Governance Pack (Weeks 4–8)

  • Evaluation harness: task suites (summarization, Q&A, code, Swahili/Sheng) — 50–100 gold items per model alias
  • PII pre-filter (Presidio-style): detect Kenya-format IDs, phone numbers, emails before logging
  • Model cards: one page per alias published to customer portal
  • CI release gate: model/quant change must pass harness before production promotion

Estimate: 1 ML engineer × 3 weeks

6 — P1: GPU Tier & Advanced Features (Months 3–6)

B1 — GPU Inference Tier (Months 3–5)

Reduces first-token latency for qwen-heavy, coder, vision from 30–120s (CPU) to <3s (GPU warm).

  • Provision GPU nodes: 1× NVIDIA L4 24GB (GPU-1: qwen-heavy + coder), 1× GPU-2: vision/LLaVA
  • Deploy ollama-gpu StatefulSet with node affinity + GPU resource limits
  • Update LiteLLM config: heavy/coder/vision aliases → ollama-gpu; granite-nano/embed/qwen-fast → ollama-cpu
  • KEDA ScaledObject on LiteLLM queue depth / GPU util ≥ 75% for 5 min
  • Fallback: if ollama-gpu health fails → route to CPU pool with latency-warning header logged
  • Grafana dashboard: GPU Inference Latency & Throughput

Estimate: 2 engineers × 3–4 weeks (+ hardware procurement lead time)

GitOps Multi-Region Pattern

  • Single git repo: i3technologies/i3-agentic-ai-labs (already in use)
  • Per-region Kustomize overlays: overlays/frankfurt/, overlays/nairobi/, overlays/burst/
  • ArgoCD App-of-Apps in Frankfurt watches all three overlays
  • Model artifacts: nightly sync of Ollama model blobs from Frankfurt → Nairobi registry (models are not customer data — residency applies to prompts/docs/logs only)
  • Secrets: OpenBao (Frankfurt primary) with Nairobi replica — same unseal ceremony, region-specific keys for data-at-rest
  • Failover: manual runbook v1 (RTO 4h). Automated DNS failover in P3.
