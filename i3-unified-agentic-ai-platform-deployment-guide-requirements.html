3. Deployment Phases

Total estimated time: ~90–100 minutes. Phases 0–2 are instant. ROKS provisioning (Phase 1) dominates at ~70 min.

PHASE 0 Local Setup — Load Environment & Validate CLI ~5 min 
# 1. Load .env into session — sets all TF_VAR_* and IBMCLOUD_API_KEY
. .\platform\scripts\load-env.ps1

# Expected: "Loaded N environment variables. Key values set: IBMCLOUD_API_KEY : Hz4n9...[redacted]"

# 2. Validate IBM Cloud CLI login, region, resource group, and plugins
.\platform\scripts\validate-step3.ps1
# All 9 checks must pass

# If not logged in:
ibmcloud login --apikey $env:IBMCLOUD_API_KEY -r eu-de -g i3-production
PHASE 1 Terraform — VPC, COS, IAM, ROKS ~70 min 
# 3. Import orphaned IAM resources (safe to run on clean state too)
.\platform\scripts\terraform-import-iam.ps1

# 4. Plan — review what will be created
cd platform\terraform
terraform plan -var="ibmcloud_api_key=$env:IBMCLOUD_API_KEY" -out=tfplan.out
cd ..\..
# Review: VPC + 3 subnets + security groups, 4 COS buckets,
#         IAM service IDs + trusted profile, ROKS 4.15 cluster

# 5. Apply (starts ROKS provisioning — ~70 min)
cd platform\terraform
terraform apply tfplan.out
cd ..\..

# Monitor worker node status in a second terminal:
make watch-workers

# 6. After apply: fetch kubeconfig
ibmcloud ks cluster config --cluster i3-platform
oc cluster-info
Terraform creates: VPC (3 subnets across eu-de zones), 4 COS buckets (tfstate, postgres-backup, seaweedfs-dr, platform-data), IAM (Tekton CI service ID, ArgoCD deploy service ID, DevOps access group, workload trusted profile), ROKS 4.15 (2× bx2.4x16 CPU workers + GPU burst pool at 0).
PHASE 2 Namespace & Policy Layer ~2 min 
# 7. Apply 11 managed namespaces + ResourceQuotas + NetworkPolicies + LimitRanges
make deploy-namespaces

# Verify all namespaces exist and solution-01..08 are untouched
make verify-namespaces
PHASE 3 OLM Operators — PostgreSQL, Kafka, OpenBao, Keycloak ~5 min apply / ~10 min until Ready 
# 8. Install OLM subscriptions (Crunchy Postgres, Strimzi, RHSSO)
oc apply -f platform/operators/subscriptions/operator-subscriptions.yaml
oc rollout status deployment -n openshift-operators --timeout=5m

# 9. Apply all operator CRs
make deploy-operators

# Monitor (open 4 separate terminals or use watch):
oc get pods -n i3-data      -w   # PostgreSQL HA  — expect 3 Running
oc get pods -n i3-messaging -w   # Kafka KRaft    — expect 3 Running
oc get pods -n i3-security  -w   # OpenBao        — expect 3 Running (sealed)
oc get pods -n i3-auth      -w   # Keycloak       — expect 2 Running
PHASE 4 OpenBao Bootstrap — Manual Gate ⚠ ~10 min
⚠ Critical manual step. OpenBao pods start sealed. This must be completed before any application can read secrets. Unseal keys must be stored in an offline HSM or paper vault — never committed to git.
# 10. Initialize (5 shares, threshold 3) — save output immediately
oc exec -n i3-security openbao-0 -- bao operator init \
  -key-shares=5 -key-threshold=3 -format=json > /tmp/openbao-init.json
#  ⚠ Copy /tmp/openbao-init.json to offline storage NOW

# 11. Add 3 unseal keys to .env, then unseal all pods:
#   OPENBAO_UNSEAL_KEY_1=<key1>
#   OPENBAO_UNSEAL_KEY_2=<key2>
#   OPENBAO_UNSEAL_KEY_3=<key3>
. .\platform\scripts\load-env.ps1
.\platform\scripts\unseal-openbao.ps1

# 12. Apply bootstrap Job (configures KV v2, K8s auth, namespace policies)
ROOT_TOKEN=$(cat /tmp/openbao-init.json | jq -r '.root_token')
oc create secret generic openbao-root-token \
  -n i3-security --from-literal=token=$ROOT_TOKEN
oc apply -f platform/operators/openbao/openbao-bootstrap-scripts.yaml
oc wait --for=condition=complete job/openbao-bootstrap -n i3-security --timeout=5m

# 13. Revoke root token — MANDATORY security step
oc exec -n i3-security openbao-0 -- bao token revoke $ROOT_TOKEN
oc delete secret openbao-root-token -n i3-security
PHASE 5 Populate Application Secrets into OpenBao ~5 min
Run before revoking the root token (or create a short-lived admin token first).
# 14. Write all secrets to KV v2 — generates random keys for LiteLLM, Langfuse,
#     Directus, n8n, Grafana, PostgreSQL pgBouncer, Admissions, watsonx, Registry
$env:OPENBAO_ROOT_TOKEN = "<root-token-from-step-12>"
