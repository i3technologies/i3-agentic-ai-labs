Rules Improvement Suggestions

SUG-R1 — Create AGENTS.md at workspace root

Bob auto-loads AGENTS.md from the project root. It is version-controlled, loaded after mode-specific rules, and is the standard onboarding entry point. Add: mode selection guide, test commands (pytest platform/, npm test, go test ./...), and HC-7 reminder.

SUG-R2 — Add rules-{mode-slug}/ supplementary directories

Bob supports mode-specific rule directories that load only when that mode is active. Create rules-i3-remediation/, rules-i3-mesh-architect/, rules-i3-fabric-blockchain/, and rules-i3-audit/ with detailed reference files. This moves deep per-mode guidance out of global token overhead.

SUG-R3 — Keep all rules files under 500 tokens each

Both current files are ~300 tokens each — optimal. The fixed Rules budget is ~600 tokens total. Maintain this discipline as you add mode-specific rules.

MCP Improvement Suggestions

SUG-M1 — Add scan_for_bypass_auth tool to guard server

HC-7 requires scanning for DEV_BYPASS_AUTH=true on every PR. A read-only grep tool added to i3_bob_mcp_server.py and auto-approved would close this gap with zero new dependencies.

SUG-M2 — Add check_rls_policy tool to guard server

The current audit_sql_ast tool catches injection patterns but does not verify ENABLE ROW LEVEL SECURITY and a tenant_isolation policy are present on every new table. A dedicated tool would enforce HC-4 DDL completeness.

SUG-M3 — Consider adding GitHub MCP server from the marketplace

Tekton CI/CD and GitOps are central to every phase delivery. The Bob Marketplace offers GitHub MCP integration for PR creation, issue tracking, and branch status — enabling the built-in create_pr_workflow end-to-end without leaving the IDE.

7.2 Hooks — Not Configured

Gap: .bob/settings.json does not exist. Hooks run shell commands automatically at Bob lifecycle events — without user intervention.
Hook EventWhen It RunsSuggested Use
SessionStartNew task startsInject current git branch + last commit into Bob's context
UserPromptSubmitBefore prompt is processedBlock prompts trying to write DEV_BYPASS_AUTH=true (HC-7)
PreToolUseBefore tool approvalBlock specific dangerous commands from executing
PostToolUseAfter file write succeedsRun grep credential scan after every write_file / apply_diff
StopAfter task loop endsRecord phase completion metrics

Recommended Hook 1 — SessionStart git context injection

// .bob/hooks/session-context.mjs
import { spawnSync } from "node:child_process";
const branch = spawnSync("git", ["branch", "--show-current"], { encoding: "utf8" }).stdout.trim();
const commit = spawnSync("git", ["log", "-1", "--oneline"], { encoding: "utf8" }).stdout.trim();
process.stdout.write(`Git context: branch=${branch} | last-commit: ${commit}\n`);

Recommended Hook 2 — PostToolUse secret scan after file writes

// .bob/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "^(write_file|apply_diff|search_and_replace|insert_content)$",
      "hooks": [{ "type": "command", "command": "node .bob/hooks/post-write-scan.mjs", "timeout": 15 }]
    }]
  }
}
