A. OpenBao / Vault — Secrets Management

Public URL https://vault.i3technologies.co.ke Namespacei3-security Internal Address openbao-active.i3-security.svc:8200 Purpose Centralised secrets management — API keys, database passwords, TLS certificates
⚠ Critical: Root Token & Unseal Keys The Vault root token is not stored in any Kubernetes secret. It was generated at initialisation time and must be held securely by the IT team (e.g., in a hardware security module, password manager, or physical safe). If the root token is lost, Vault must be re-initialised and every secret re-entered from scratch.

Vault uses Shamir secret sharing: 3 of 5 unseal keys are required to unseal after every restart. All 5 keys must be stored externally. Losing >2 keys permanently locks the Vault.

Admin Guide

1 — Unsealing After a Restart

Vault seals itself whenever the pod restarts. Until unsealed, all secrets are inaccessible.

# Check current seal status
vault status -address=https://vault.i3technologies.co.ke

# Unseal — run this 3 times, each with a different unseal key
vault operator unseal -address=https://vault.i3technologies.co.ke
# Enter unseal key when prompted — repeat with key #2 and key #3

Watch for Sealed: false and Unseal Progress: 3/3 after the third command.

2 — Logging In as Admin

# Using root token (initial setup only — use a named token in production)
vault login -address=https://vault.i3technologies.co.ke
# Enter root token when prompted

# Or via environment variable
export VAULT_ADDR=https://vault.i3technologies.co.ke
export VAULT_TOKEN=<root-token>
vault status

3 — Creating a KV Secrets Engine

vault secrets enable -path=i3platform kv-v2
# Verify
vault secrets list

4 — Writing and Reading Secrets

# Write a secret
vault kv put i3platform/database \
  host="postgres.i3-data.svc:5432" \
  username="appuser" \
  password="s3cur3p@ss"

# Read a secret
vault kv get i3platform/database

# Read single field
vault kv get -field=password i3platform/database

5 — AppRole Authentication (for Applications)

Applications authenticate to Vault using AppRole — they present a role_id and secret_id to receive a short-lived token.

# Enable AppRole auth method
vault auth enable approle

# Create a role (e.g., for the EvalOS backend)
vault write auth/approle/role/evalos \
  token_policies="evalos-policy" \
  token_ttl=1h \
  token_max_ttl=4h \
  secret_id_ttl=24h

# Retrieve role_id (shared with the app at deploy time)
vault read auth/approle/role/evalos/role-id

# Generate a secret_id (rotated regularly)
vault write -f auth/approle/role/evalos/secret-id

6 — Writing a Policy

# evalos-policy.hcl
path "i3platform/data/evalos/*" {
  capabilities = ["read", "list"]
}

# Upload policy
vault policy write evalos-policy evalos-policy.hcl

7 — Rotating Secrets

# Update a secret (creates a new version; old version is preserved)
vault kv put i3platform/database password="n3wP@ss!"

# Delete old versions if needed
vault kv delete i3platform/database  # soft delete of latest
vault kv destroy -versions=1 i3platform/database  # hard delete version 1

8 — Enabling Audit Logs

# Log to file inside the pod
vault audit enable file file_path=/vault/logs/audit.log

# View audit log
oc exec -n i3-security deploy/openbao -- cat /vault/logs/audit.log | tail -50
ℹ User Guide Vault is infrastructure-only. End-users and developers do not access Vault directly. Applications receive credentials via Kubernetes secrets injected at deploy time or through the AppRole API. Contact the IT administrator if a service is reporting missing or expired credentials.

B. Grafana / Prometheus — Monitoring & Observability

Grafana URL https://grafana.i3technologies.co.ke Namespacei3-monitoring Prometheusprometheus-k8s in openshift-monitoring Purpose Monitor all pods, resource usage, and custom application metrics across the i3 platform

Retrieving Admin Credentials

Grafana admin credentials are stored in the grafana-admin secret in the i3-monitoring namespace:

oc get secret grafana-admin -n i3-monitoring \
  -o jsonpath="{.data.admin-password}" | base64 -d

Log in at https://grafana.i3technologies.co.ke with username admin and the decoded password.

Admin Guide

1 — Creating a Dashboard

  1. Click + → New Dashboard in the left sidebar.
  2. Click Add visualisation → select data source Prometheus.
  3. Enter a PromQL query (example below), configure panel type (Graph, Gauge, Stat), and click Apply.
  4. Click the floppy-disk icon to save. Give the dashboard a meaningful name and folder.
# Example — CPU usage for all pods in a namespace
sum(rate(container_cpu_usage_seconds_total{namespace="i3-engage"}[5m]))
  by (pod)

# Memory usage (bytes)
sum(container_memory_working_set_bytes{namespace="i3-evalos"})
  by (pod)

2 — Adding a Data Source

  1. Go to Connections → Data Sources → Add data source.
  2. Select Prometheus.
  3. URL: https://prometheus-k8s.openshift-monitoring.svc:9091
  4. Enable Skip TLS verify (internal cluster CA) or add the CA cert.
  5. Click Save & Test.

3 — Setting Up Alerts

  1. Open a panel → Edit → Alert tab.
  2. Set condition (e.g., IS ABOVE 80 for CPU %).
  3. Configure a notification channel: Alerting → Contact points → Add contact point (email, Slack, webhook).
  4. Set Notification policy to route alerts to the correct contact.

4 — Importing a Community Dashboard

  1. Browse grafana.com/grafana/dashboards and copy the dashboard ID.
  2. In Grafana: + → Import → Enter dashboard ID → Load.
  3. Select the Prometheus data source and click Import.

Recommended IDs: 315 (Kubernetes cluster monitoring), 12740 (Kafka overview), 3662 (Prometheus internal).

User Guide

Navigating Dashboards

After logging in, click Dashboards in the left sidebar to browse available dashboards. Use the folder structure to find platform-specific boards (e.g., i3 Platform / EvalOS).

Reading Pod CPU & Memory Charts

  • CPU panel — shows cores consumed over time. Spikes indicate heavy processing; sustained near-limit values suggest the pod needs more resources.
  • Memory panel — shows working-set memory in MiB/GiB. A continuously rising line (no drops) may indicate a memory leak.
  • Use the time range picker (top-right) to zoom into an incident window.

Viewing Alert History

Go to Alerting → Alert Rules to see all defined rules and their current state. Go to Alerting → Silences to manage maintenance windows. Historical firing events appear in Alerting → Alert rules → State history.

  name: OpenShift

  clientID: argocd
  clientSecret: <oidc-secret>
  requestedScopes: ["openid", "profile", "email", "groups"]

User Guide

Viewing Application Sync Status

The ArgoCD home screen lists all applications with a coloured status badge:

  • Synced (green) — live cluster matches the Git repo.
  • OutOfSync (yellow) — changes exist in Git that have not been deployed.
  • Degraded (red) — resources are unhealthy (pods crashing, etc.).
  • Unknown — ArgoCD cannot reach the resource; check permissions.

Triggering a Manual Sync

  1. Open the application tile and click SYNC.
  2. Review the list of resources to be changed.
  3. Click Synchronize to confirm.

Viewing Diff Between Git and Live

Open the application → click DIFF to see a line-by-line comparison between the desired state (Git) and the current live state on the cluster.

Checking Deployment History

Open the application → click the History and Rollback icon (clock icon, top-right panel) to see all past syncs with commit SHA, timestamp, and author.

Developer / User Guide

Transcribing Audio — API

POST audio as multipart/form-data to the transcription endpoint:

curl -X POST https://stt.i3technologies.co.ke/v1/transcribe \
  -F "audio=@recording.mp3" \
  -F "language=en"

Supported language codes:

  • en — English
  • sw — Swahili (Kiswahili)

Sample successful response:

{
  "text": "The student correctly identified the solution.",
  "language": "en",
  "duration_seconds": 4.2,
  "segments": [...]
}

JavaScript SDK Example (Browser)

const formData = new FormData();
formData.append("audio", audioBlob, "recording.webm");

const res = await fetch("https://stt.i3technologies.co.ke/v1/transcribe", {
  method: "POST",
  body: formData,
});

console.log("Transcript:", text);

Developer Guide

Synthesising Speech — API

POST a JSON body to /v1/synthesize. The response is a audio/wav stream.

curl -X POST https://tts.i3technologies.co.ke/v1/synthesize \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Welcome to the i3 platform. Your assessment will begin shortly.",
    "voice": "en_US-lessac-medium",
    "speed": 1.0
  }' \
  --output response.wav

Request Parameters

ParameterTypeRequiredDescription
textstringYesText to synthesise (max 5 000 chars)
voicestringYesVoice ID (see table above)
speedfloatNoPlayback speed multiplier (0.5–2.0, default 1.0)
formatstringNowav (default) or mp3

JavaScript Example

const res = await fetch("https://tts.i3technologies.co.ke/v1/synthesize", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    text: "Karibu kwenye mfumo wa i3.",
    voice: "sw_KE-swahili-medium",
  }),
});
const audioBlob = await res.blob();
const url = URL.createObjectURL(audioBlob);
new Audio(url).play();

G. Admissions Agent

URL https://admissions.i3technologies.co.ke Health Check https://admissions.i3technologies.co.ke/health Namespacei3-admissions Keycloak Clientadmissions-widget Purpose AI-powered student admissions — integrates with Engage (WhatsApp intake) and EvalOS (entry testing)

Admin Guide

1 — Viewing Applications

Navigate to Admissions Dashboard → All Applications. Filter by status:

  • Submitted — applicant has completed the form.
  • Under Review — entry test scheduled or in progress via EvalOS.
  • Approved — admission granted; SIT enrollment triggered.
  • Rejected — admission denied; automated notification sent.
  • Waitlisted — deferred pending cohort capacity.

  1. Open an application → review personal details, uploaded documents, and EvalOS entry test score.
  2. Click Approve or Reject.
  3. On approval, the system automatically:
    • Creates a Keycloak account for the student.
    • Triggers the Onboarding Agent (see §H).
    • Publishes a sit.enrollments event to Kafka.
    • Sends a welcome email via n8n.

3 — Integration with WhatsApp (Engage)

When a prospective student messages the admissions WhatsApp number, Engage routes the conversation to the Admissions Agent. The agent collects required information conversationally and creates a draft application. Admins can view these draft applications under Applications → Draft (Engage).

H. Onboarding Agent

URL https://onboarding.i3technologies.co.ke Health Check https://onboarding.i3technologies.co.ke/health Namespacei3-onboarding Purpose Automated new-user onboarding — welcome emails, Keycloak account creation, n8n workflow triggers

Admin Guide

1 — How Onboarding Works

The Onboarding Agent is triggered automatically by an event (typically from the Admissions Agent or by an admin manually enrolling a user). On trigger, it:

  1. Creates or updates the Keycloak account in the i3 realm with the correct roles.
  2. Sends a welcome email containing the login URL and temporary password.
  3. Publishes a sit.enrollments event to Kafka so downstream services (LMS, SmartLab, etc.) can provision the user.
  4. Triggers a configurable n8n workflow for institution-specific steps (e.g., printing an ID card, assigning a locker).

2 — Configuring Onboarding Flows

Onboarding flows are defined via the Onboarding Agent admin panel at https://onboarding.i3technologies.co.ke:

  • Flows — define step sequences per user type (Student, Staff, Instructor).
  • Templates — customise email and WhatsApp welcome message templates (supports Handlebars variables: {{firstName}}, {{courseTitle}}, etc.).
  • n8n Webhooks — configure the n8n webhook URL to call at each step.
  • Keycloak Mapping — map user type to Keycloak realm roles.

✔ Naming Convention Use domain.entity.action (e.g., sit.enrollments, ford.membership.verified). Keep names lowercase with dots as separators. Avoid underscores to be consistent with the existing inventory.

Python Example

from kafka import KafkaProducer, KafkaConsumer
import json

# Producer
producer = KafkaProducer(
    bootstrap_servers="kafka-bootstrap.i3-messaging.svc.cluster.local:9092",
    value_serializer=lambda v: json.dumps(v).encode("utf-8"),
)
producer.send("ford.membership.registrations", {"memberId": "frd-456", "name": "Jane Doe"})
producer.flush()

# Consumer
consumer = KafkaConsumer(
    "ford.membership.verified",
    bootstrap_servers="kafka-bootstrap.i3-messaging.svc.cluster.local:9092",
    group_id="ford-verification-service",
    value_deserializer=lambda m: json.loads(m.decode("utf-8")),
)
for message in consumer:
    print(f"Verified: {message.value}")
