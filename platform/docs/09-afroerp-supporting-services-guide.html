A4. KRA eTIMS Setup

Action Required: The KRA eTIMS secret currently contains placeholder values. Follow these steps to configure it before processing any invoices.

Step 1 — Update the Kubernetes secret

oc project i3-afroerp

# Edit the eTIMS secret directly
oc edit secret afroerp-etims-secret

# Or patch individual values (base64-encode your values first)
echo -n "YOUR_KRA_CLIENT_ID"     | base64
echo -n "YOUR_KRA_CLIENT_SECRET" | base64
echo -n "YOUR_KRA_PIN"           | base64

oc patch secret afroerp-etims-secret \
  --type='json' \
  -p='[
    {"op":"replace","path":"/data/KRA_CLIENT_ID",     "value":"BASE64_CLIENT_ID"},
    {"op":"replace","path":"/data/KRA_CLIENT_SECRET",  "value":"BASE64_CLIENT_SECRET"},
    {"op":"replace","path":"/data/KRA_PIN",            "value":"BASE64_KRA_PIN"}
  ]'

Step 2 — Restart the ERPNext pod to pick up new env vars

oc rollout restart deployment/afroerp -n i3-afroerp
oc rollout status deployment/afroerp -n i3-afroerp

Step 3 — Configure eTIMS in ERPNext UI

1
Open eTIMS Settings Navigate to Accounts → Settings → KRA eTIMS Settings (or search "eTIMS"). Enter the API URL: https://etims-api.kra.go.ke.
2
Enter credentials Paste the Client ID, Client Secret, and KRA PIN obtained from the KRA eTIMS portal. Click Save.
3
Enable auto-submission Tick Auto Submit Invoices to eTIMS on Submit. This triggers the eTIMS API call each time a Sales Invoice is submitted in ERPNext.
4
Test the connection Click Test Connection. A success toast confirms the credentials are valid. If it fails, re-check the KRA_PIN format and that your IP is whitelisted by KRA.

C — Admin Guide

C1. Collections & Fields

In Directus, a Collection is equivalent to a database table. Fields are the columns within that collection.

1
Create a collection — Log in at https://cms.i3technologies.co.ke. Go to Settings → Data Model → + Create Collection. Enter the collection name (snake_case, e.g., course_materials). Choose a primary key type (usually Auto-Increment Integer or UUID).
2
Add fields — Inside the collection, click + Create Field. Select the field type (String, Integer, Datetime, Image, Relation, etc.). Configure validation rules, defaults, and display options.
3
Set up relations — Use Many-to-One, One-to-Many, or Many-to-Many field types to link collections (e.g., courses → modules → lessons).

C2. User & Role Management

1
Create a role — Settings → Roles & Permissions → + Create Role. Name the role (e.g., Content Editor). Set per-collection permissions: create, read, update, delete, share.
2
Invite a user — User Management → + Invite User. Enter the email; they receive an invitation link. Assign the user to one or more roles.
3
Public role — The built-in Public role controls what unauthenticated API requests can access. For any collection exposed publicly (e.g., blog posts), grant read-only permissions to the Public role.

D-U2. Understanding Workflows

An n8n workflow is a visual flowchart of nodes connected by edges.

  • Trigger node (leftmost, green border) — Starts the workflow. Types: Webhook, Schedule (cron), Manual, or application-specific events.
  • Action nodes — Perform operations: HTTP requests, database queries, data transformations, send notifications.
  • Logic nodes — IF, Switch, Merge, Loop — control flow based on data conditions.
  • Data flows — Each node passes JSON items to the next. Expressions like {{ $json.email }} reference upstream data.

To view a workflow without editing: click its name → the canvas opens in read-only mode if you have Viewer access only.

1

Common oc commands cheat sheet

# Switch project
oc project <namespace>

# Get all resources
oc get all -n <namespace>

# Describe a pod (events, resource limits)
oc describe pod <pod-name> -n <namespace>

# Get pod logs (last 100 lines)
oc logs --tail=100 <pod-name> -n <namespace>

# Execute a shell in a pod
oc exec -it <pod-name> -n <namespace> -- /bin/bash

# Restart a deployment
oc rollout restart deployment/<name> -n <namespace>

# View secrets (base64-encoded values)
oc get secret <secret-name> -o yaml -n <namespace>

# Decode a secret value
oc get secret <secret-name> -o jsonpath='{.data.MY_KEY}' -n <namespace> | base64 -d

# Check PVC usage
oc get pvc -n <namespace>
