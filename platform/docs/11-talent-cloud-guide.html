Admin Guide

1. Platform Architecture

Talent Cloud is the central talent marketplace for the i3 Technologies platform. It ingests graduates from SIT Work-Centers, enriches candidate profiles with certification scores from EvalOS, exposes a recruiter-facing API for job postings, and runs LiteLLM Mistral inference to score candidate–job fit in real time.

🎓 SIT Work-Centers Graduates auto-sync into talent_db via write-through on sit-api
📊 EvalOS Bridge Certification scores populate the skills graph for each candidate
🤖 LiteLLM / Mistral Scores candidate profiles against job requirements, returns ranked list
🗄️ talent_db (PostgreSQL) 9 tables — candidates, skills, jobs, placements, bench_status, feedback …
🔐 Keycloak SSO Roles: talent-candidate, talent-recruiter. Client: talent-web
📁 SeaweedFS talent-cvs · talent-certs · talent-reports buckets

Data Flow Summary

  1. SIT graduate completes a work-centre cohort → sit-api writes candidate row to talent_db.candidates via write-through.
  2. EvalOS assessment result posted → bridge event updates candidate_skills with normalised score.
  3. Recruiter creates a job listing via POST /api/v1/jobs.
  4. Recruiter calls POST /api/v1/match → Talent API queries bench, scores via Mistral, returns ranked candidates.
  5. Recruiter confirms placement via placement API → candidate moves off bench.
Namespace isolation All workloads run in the i3-talent Kubernetes namespace. Database credentials, Keycloak secrets, and SeaweedFS endpoints are stored as Kubernetes Secrets within that namespace.

3. Skills Graph Management

The skills graph is a normalised taxonomy stored across three tables: skills (master list), candidate_skills (candidate–skill associations with scores), and assessments (raw EvalOS assessment records).

Skills Taxonomy

Skills are pre-seeded categories. Administrators can add new skills directly in the database:

-- Add a new skill to the master taxonomy
INSERT INTO skills (skill_id, name, category, description)
VALUES ('sk_k8s', 'Kubernetes', 'DevOps', 'Container orchestration with Kubernetes');

Associating Skills with a Candidate

Skill associations are created automatically by the EvalOS bridge, but can also be set manually:

-- Manually associate a skill score
INSERT INTO candidate_skills (candidate_id, skill_id, score, source, updated_at)
VALUES ('cnd_8a3f2901c', 'sk_k8s', 82, 'manual', NOW())
ON CONFLICT (candidate_id, skill_id) DO UPDATE SET score = EXCLUDED.score;

Skills Schema Reference

TableKey ColumnsNotes

5. AI Matching — How It Works

The AI match pipeline uses LiteLLM with Mistral to generate a nuanced relevance score for each bench candidate against a job listing. Hard skill threshold filtering occurs first, then Mistral produces a ranked list with explanations.

Matching Pipeline Steps

  1. Bench pull — Talent API fetches all candidates with bench_status = available.
  2. Hard filter — Candidates missing any required skill (below min_score) are eliminated before calling Mistral.
  3. Prompt construction — API builds a structured prompt: job description + required skills + each candidate's skill profile and scores.
  4. Mistral inference — LiteLLM routes the prompt to the Mistral model, which returns a weighted fit score (0–100) and a short rationale per candidate.
  5. Ranked response — Results are sorted by Mistral score descending and returned to the recruiter.
  6. Report storage — The full ranked result is saved to SeaweedFS talent-reports bucket for audit.

6. Bench Management

The bench is the pool of candidates who are actively available for placement. Bench status is tracked in the bench_status table and mirrored on the candidates row.

bench_status valueMeaningAppears in /bench?
availableReady and seeking placementYes
placedCurrently on active placementNo
unavailableNot seeking — training, leave, etc.No
pendingProfile incomplete / under reviewNo

List Available Bench Candidates

GET https://api.talent.i3technologies.co.ke/api/v1/bench

Returns all candidates with bench_status = available, ordered by date added to bench (oldest first — longest waiting).

Moving Candidates On/Off Bench (DB)

-- Move candidate to bench (available)
UPDATE bench_status
SET status = 'available', available_since = NOW()
WHERE candidate_id = 'cnd_8a3f2901c';

-- Move candidate off bench after placement
UPDATE bench_status
SET status = 'placed', placed_at = NOW()
WHERE candidate_id = 'cnd_8a3f2901c';
Bench status consistency Always update both bench_status table and candidates.bench_status column together, or use the placement API endpoint which handles both transactionally.

7. SIT Work-Centers Bridge

When a learner completes a SIT Work-Center cohort, the sit-api fires a write-through event that creates a corresponding candidate profile in talent_db. No manual import is required.

Bridge Behaviour

  • Trigger: Cohort completion event in SIT (cohort_status = graduated).
  • Action: sit-api calls POST /api/v1/candidates with source: sit-workcenter and links evalos_passport_id if the learner has an EvalOS record.
  • Default bench status: New graduates land with bench_status = pending until a talent-recruiter reviews and approves (available).
  • Deduplication: The API checks keycloak_sub uniqueness; duplicate submissions are silently ignored (idempotent).

Verifying Bridge Sync

-- Check recent SIT-sourced candidates
SELECT candidate_id, full_name, created_at, bench_status
FROM candidates
WHERE source = 'sit-workcenter'
ORDER BY created_at DESC
LIMIT 20;
SIT namespace The SIT Work-Centers API runs in namespace i3-sit. The service account used for write-through is sit-talent-bridge, granted the talent-recruiter Keycloak role.

8. EvalOS Bridge

EvalOS is the certification and assessment platform (Component 10). When a candidate completes an assessment, EvalOS posts the result to the Talent API, which normalises the score and updates the candidate's skills graph.

Bridge Flow

  1. Learner completes an EvalOS assessment linked to a skill (e.g., Python Fundamentals).
  2. EvalOS posts the result to POST /api/v1/assessments (internal endpoint, not publicly documented).
  3. Talent API resolves the evalos_passport_id to a candidate_id.
  4. Raw score is normalised to 0–100 and upserted into candidate_skills.
  5. A raw record is preserved in the assessments table for audit.

Verifying Assessment Sync

-- View latest assessments for a candidate
SELECT a.assessment_id, s.name AS skill, a.raw_score,
       a.normalised_score, a.assessed_at
FROM assessments a
JOIN skills s ON a.skill_id = s.skill_id
WHERE a.candidate_id = 'cnd_8a3f2901c'
ORDER BY a.assessed_at DESC;

11. Troubleshooting

SymptomLikely CauseResolution
POST /api/v1/candidates returns 409 Conflict keycloak_sub already exists in candidates Candidate already registered. Use GET /api/v1/candidates?keycloak_sub=... to retrieve existing record.
POST /api/v1/match returns 0 candidates All bench candidates failed hard skill filter Lower min_score thresholds in skills_req, or check that candidate skills have been synced from EvalOS.
LiteLLM timeout on /match Mistral model endpoint unreachable or overloaded Check LiteLLM proxy pod: kubectl logs deploy/litellm -n i3-ai. Verify API key and model availability.
SIT graduates not appearing in talent_db SIT bridge write-through failing silently Check sit-api logs in i3-sit namespace for HTTP 4xx/5xx on bridge calls. Verify sit-talent-bridge service account token is valid.
EvalOS scores not updating candidate_skills Bridge event not firing, or evalos_passport_id mismatch Confirm evalos_passport_id is set on the candidate row. Check EvalOS bridge logs. Run manual SQL upsert if needed.
CV upload returns 413 Payload Too Large File exceeds SeaweedFS ingress limit (default 20 MB) Compress PDF or increase ingress body size in the SeaweedFS ingress annotation: nginx.ingress.kubernetes.io/proxy-body-size: "50m".
Keycloak 401 on API calls Token expired or wrong role Re-authenticate. Ensure the user has talent-recruiter role for job/match endpoints, or talent-candidate for profile endpoints.
talent-api pod in CrashLoopBackOff DB connection failure at startup Verify the talent-db-secret Kubernetes Secret is present and correct. Check PostgreSQL pod health in i3-data namespace.
GET /api/v1/bench returns stale data Candidate bench_status column not updated after placement Check placements table for recent inserts. Run consistency check query between bench_status table and candidates.bench_status column.

Consistency Check Query

-- Find mismatches between bench_status table and candidates column
SELECT c.candidate_id, c.bench_status AS cand_col, b.status AS bench_tbl
FROM candidates c
JOIN bench_status b ON c.candidate_id = b.candidate_id
WHERE c.bench_status != b.status;
User Guide — Candidates & Recruiters

C1. Registering Your Profile (Candidates)

Your Talent Cloud profile is the foundation for job matching. It contains your contact details, location, skills, and CV. Profiles can be created by an admin on your behalf (e.g. after graduating from a SIT Work-Center), or you can register directly.

How to Register

  1. Log in to talent.i3technologies.co.ke using your i3 SSO credentials (Keycloak).
  2. Navigate to Profile → Create Profile. Your name and email are pre-filled from Keycloak.
  3. Fill in your phone number and location (city, country).
  4. If you have an EvalOS passport ID, enter it in the EvalOS ID field — this links your certification scores automatically.
  5. Click Save Profile. Your profile is created with status pending until reviewed by a recruiter.
SIT Work-Center graduates If you completed a SIT Work-Center cohort, your profile was likely created automatically. Log in to verify it exists and update your phone and location.

C2. Uploading Your CV (Candidates)

A current CV significantly improves your visibility to recruiters. Upload a PDF of your CV through your profile page.

Steps

  1. Navigate to Profile → Documents.
  2. Click Upload CV and select your PDF (max 20 MB).
  3. The CV is stored securely in the talent-cvs bucket and linked to your profile.
  4. To replace an existing CV, simply upload a new one — it overwrites the previous file.
Tip Name your CV file descriptively (e.g. AmineOmondi_CV_2025.pdf) before uploading, as the original filename is preserved in metadata.

C3. Adding Skills & Certifications (Candidates)

Skills are the core of AI matching. Scores sourced from EvalOS are authoritative; additional skills can be self-declared and will be visible to recruiters with a self-reported label.

Skills from EvalOS (Automatic)

When your EvalOS assessments are synced, your skills appear automatically under Profile → Skills with a green checkmark and a numeric score (0–100).

Adding a Self-Reported Skill

  1. Go to Profile → Skills → Add Skill.
  2. Search for the skill in the dropdown (e.g. "Docker", "React").
  3. Select your self-assessed proficiency: Beginner, Intermediate, or Advanced (mapped to scores 40, 65, 85).
  4. Optionally upload a supporting certificate under Profile → Documents → Upload Certificate.
  5. Click Save.

Uploading a Certificate

  1. Navigate to Profile → Documents → Upload Certificate.
  2. Select the certificate PDF and enter the skill it relates to.
  3. The file is stored in talent-certs and linked to your skills entry.

C4. Checking Your Bench Status (Candidates)

Your bench status determines whether you appear in recruiter searches and AI match results.

StatusWhat it means for you
availableYour profile is visible in searches and AI matching. You may receive placement offers.
pendingYour profile is under recruiter review. You are not yet visible in search results.
placedYou are on an active placement. Not visible in new match results.
unavailableYou have marked yourself as unavailable (e.g. taking a course). Not visible in searches.

Updating Your Availability

  1. Go to Profile → Availability.
  2. Toggle your status between Available and Unavailable.
  3. If you are on an active placement, only a recruiter can change your status to placed.

C5. Responding to Job Opportunities (Candidates)

When a recruiter runs an AI match and your profile ranks highly, you may receive a notification or direct contact from the recruiter.

Viewing Job Listings

  1. Navigate to Jobs → Browse Listings to see active opportunities.
  2. Each listing shows the title, client name, required skills, and a match indicator if your profile has been scored.
  3. Click a listing to view the full description and required skills with your score gap (if any).

Expressing Interest

  1. On a job listing, click Express Interest.
  2. This flags your profile to the recruiter managing that listing.
  3. The recruiter will contact you directly if they decide to proceed with a placement.

R1. Creating a Job Listing (Recruiters)

Job listings define the requirements used by the AI matching engine. A well-constructed skills_req array with accurate weights produces the most relevant match results.

Via the Web UI

  1. Log in with your talent-recruiter account at talent.i3technologies.co.ke.
  2. Navigate to Jobs → New Listing.
  3. Fill in Title, Client, and Description.
  4. Under Required Skills, search for each skill, set the minimum score threshold, and assign a weight (all weights must total 1.0).
  5. Click Publish. The listing is immediately active and can be used for AI matching.

Via the API

See the Job Listings Management section above for the full API request/response example with skills_req JSON format.

R2. Running AI Match (Recruiters)

AI matching queries the bench, applies hard skill filters, and uses Mistral to rank remaining candidates. The process takes 5–15 seconds depending on bench size.

Via the Web UI

  1. Navigate to Jobs → [Select a listing] → Run AI Match.
  2. Click Start Matching. A loading indicator appears while Mistral processes the candidates.
  3. Once complete, you are redirected to the ranked candidates view.
  4. A match report JSON is automatically saved to SeaweedFS for audit.

Via the API

curl -X POST https://api.talent.i3technologies.co.ke/api/v1/match \
  -H "Authorization: Bearer <your-token>" \
  -H "Content-Type: application/json" \
  -d '{"job_id": "job_c3f1a8b"}'
Empty match results If the result returns zero candidates, all bench candidates failed the hard skill filter. Lower min_score values on the job listing or check whether candidate skill profiles are up to date with EvalOS data.

R3. Reviewing Ranked Candidates (Recruiters)

The AI match result presents candidates ranked by match score (highest first) with a Mistral-generated rationale for each.

Reading the Results

ColumnDescription
RankRelative position (1 = best fit)
Match ScoreMistral composite score 0–100
RationaleAI-generated explanation of strengths/gaps
Skills SummaryCandidate's actual score for each required skill
CV / Profile linkLinks to full profile and CV document

Filtering and Shortlisting

  1. Use the minimum match score slider to narrow the visible list (e.g., show only candidates scoring 80+).
  2. Click Shortlist on candidates you want to progress with — this marks them for follow-up without affecting their bench status.
  3. Click a candidate's name to view their full profile, skills timeline, and CV.

R4. Making a Placement (Recruiters)

A placement confirms that a candidate has been assigned to a job. This moves the candidate off the bench and records the placement in the audit tables.

Confirm a Placement via API

{
  "candidate_id": "cnd_8a3f2901c",
  "job_id":       "job_c3f1a8b",
  "start_date":   "2025-02-01",
  "notes":        "Confirmed by client — 3 month contract"
}

Response 201 Created

{
  "placement_id":  "plc_f9a1b2c3",
  "candidate_id":  "cnd_8a3f2901c",
  "job_id":        "job_c3f1a8b",
  "status":        "active",
  "start_date":    "2025-02-01",

Upon successful placement creation, the API automatically:

  • Sets candidates.bench_status = placed
  • Sets bench_status.status = placed
  • Inserts a record into placement_history
  • Updates jobs.status = filled (if only one placement was needed)
