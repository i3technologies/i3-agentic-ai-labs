Part A — Administrator Guide

A1. FORD-Asili Overview & Political Context

FORD-Asili Digital PMaaS (Political Membership-as-a-Service) is a Hyperledger Fabric blockchain platform built for the Forum for the Restoration of Democracy – Asili party's 2027 Kenya General Election cycle. It provides an immutable, auditable, and privacy-preserving system for:

  • Ward-level membership registration across all 47 Kenya counties
  • AI-powered nomination management for 2027 election candidacies
  • Primary ballot processing with tamper-proof audit trail
  • Agent performance tracking (field agents who register members on the ground)

Ward-First Strategy

Kenya's electoral geography is organised into wards → sub-counties → counties → constituencies. FORD-Asili's ward-first strategy requires that every member registration captures ward identity at source. This granularity enables accurate delegate allocation, ground coverage analytics, and nomination eligibility verification.

⏰ Hard Deadline The 2027 Kenya General Elections are scheduled for 16 March 2027. The IEBC nomination window opens well before polling day. All four planned blockchain channels (membership, nominations, primaries-2027) and their associated chaincode must be live before the party's internal nomination deadline. Plan backwards from 16 March 2027 accordingly.

A2. Membership Registration Workflow

The end-to-end registration flow from field agent mobile app to confirmed blockchain record proceeds as follows:

  1. Field agent opens the FORD portal and logs in via Keycloak (role: ford-agent).
  2. Agent captures member details: national ID, phone number, ward, sub-county, county. The agent's own agent_id is injected server-side from the JWT token.
  3. App calls POST /api/v1/members/register. The API immediately SHA-256 hashes the national ID and phone number before touching any database or blockchain.
  4. API checks velocity rate: has this agent already registered ≥ 50 members today? If yes → HTTP 429.
  5. API checks duplicate hashes. If the national ID hash already exists → member is auto-flagged.
  6. A 6-digit OTP is generated and dispatched via the i3 Engage webhook to the member's phone number.
  7. Member status is set to pending and a row is inserted into otp_verifications.
  8. Member reads OTP from SMS and gives it to the agent (or enters it themselves).
  9. App calls POST /api/v1/members/verify-otp. On success, member status changes to verified.
  10. A Hyperledger Fabric transaction is submitted to the membership channel, invoking the MembershipRegistry chaincode. The hashed PII + ward metadata are written immutably to the ledger.
  11. Agent's duty count increments by 1 in agent_duty_log.

A4. OTP Verification System

Phone ownership verification is mandatory before a registration is marked verified and committed to the blockchain. This prevents registrations of fictitious or non-consenting members.

How It Works

  1. On POST /api/v1/members/register, the API generates a cryptographically random 6-digit OTP.
  2. The OTP and its expiry timestamp (default: 5 minutes / 300 seconds) are stored in the otp_verifications table, linked to the phone hash.
  3. The API fires a POST webhook to i3 Engage with the phone number and OTP payload. i3 Engage dispatches the SMS.
  4. When POST /api/v1/members/verify-otp is called, the API checks: (a) OTP matches, (b) OTP has not expired, (c) phone hash matches the stored record.
  5. On success, the row in otp_verifications is marked consumed and the member row status is updated to verified.

OTP Table Schema (otp_verifications)

ColumnTypeNotes
idUUIDPrimary key
phone_hashCHAR(64)SHA-256 of phone number
otp_codeCHAR(6)6-digit numeric OTP (hashed at rest recommended)

🚨 OTP Expiry OTPs expire after 5 minutes. If a member does not receive the SMS or enters the code late, the agent must re-trigger registration. Expired OTPs leave the member in pending status indefinitely — run a periodic cleanup job to expire stale pending records.

A5. Privacy & Data Protection

SHA-256 Hashing — Privacy by Design

FORD-Asili implements a privacy-by-design architecture. National ID numbers and phone numbers are never stored in plain text — anywhere. Not in PostgreSQL, not in the Hyperledger Fabric ledger, not in application logs.

The hashing pipeline:

// Pseudocode — executed server-side before any DB write
const national_id_hash = sha256(national_id.trim().toLowerCase());
const phone_hash       = sha256(normalise_phone(phone)); // E.164 format

// Plain-text values are discarded from memory immediately after hashing.
// They are NEVER logged, NEVER written to any store.

What Is Stored

Data ElementStored AsLocation
National IDSHA-256 hash (hex, 64 chars)members_pii, Fabric ledger
Phone numberSHA-256 hashmembers_pii, otp_verifications
Ward / Sub-county / CountyPlain textmembers_pii, Fabric ledger
Agent IDPlain textagent_duty_log, Fabric tx metadata
OTP codePlain text (short-lived, 5 min)otp_verifications only
Ballot entriesEncrypted referencesballot_entries, primaries channel

Why This Matters (Kenya Data Protection Act 2019)

Kenya's Data Protection Act 2019 mandates that personal data be processed lawfully, stored securely, and protected against unauthorised access. By storing only irreversible hashes, FORD-Asili ensures that even a complete database breach exposes no usable PII. Hash values cannot be reversed to reveal a national ID or phone number.

✅ Compliance Note Do NOT add any logging middleware that outputs raw request bodies containing national_id or phone fields. Ensure the API's request logger explicitly redacts these fields before writing to any log sink.

A6. Velocity Rate Limiting

The 50-per-Day Cap

Each field agent is limited to registering a maximum of 50 members per calendar day (resetting at 00:00 EAT). This limit is enforced at the API level before any hash or database operation.

Why This Limit Exists

  • Anti-fraud: Ballot stuffing or mass fabrication of fictitious members requires an agent to submit many registrations rapidly. A 50/day cap makes large-scale fraud economically unviable for any single actor.
  • Operational realism: A diligent field agent physically visiting members can realistically achieve 30–50 verified registrations per day. Higher counts are a red flag.
  • SMS cost control: Each registration triggers an OTP SMS via i3 Engage. Rate limiting protects against runaway SMS spend caused by misbehaving clients or compromised agent credentials.

How It Is Enforced

-- Checked before every registration insert
SELECT COUNT(*) FROM agent_duty_log
WHERE agent_id = $1
  AND DATE(created_at AT TIME ZONE 'Africa/Nairobi') = CURRENT_DATE AT TIME ZONE 'Africa/Nairobi'
  AND status IN ('pending', 'verified');

-- If COUNT >= 50 → return HTTP 429
⚠️ Temporary Limit Raise Do not raise the velocity cap without a written approval from the FORD-Asili data protection officer and the party's National Elections Board (NEB). Any change must be logged with a justification.

A9. Completing the Blockchain Setup

The following tasks must be completed in order to bring the Hyperledger Fabric network fully operational. Work through them sequentially — each step depends on the previous one.

Step 1 — Generate MSP Crypto Material

Use fabric-ca-client to enrol the orderer and peer identities against the running CAs:

# Enrol the FORD-Asili orderer identity against ford-ca
fabric-ca-client enroll \
  -u https://orderer:<password>@ford-ca.i3-ford.svc.cluster.local:7054 \
  --caname ford-ca \
  --mspdir /var/hyperledger/orderer/msp

# Enrol the i3Tech peer identity against i3tech-ca
fabric-ca-client enroll \
  -u https://peer0:<password>@i3tech-ca.i3-ford.svc.cluster.local:7054 \
  --caname i3tech-ca \
  --mspdir /var/hyperledger/peer/msp

Mount the generated MSP directories into the respective pod volumes via Kubernetes Secrets or PVC.

Step 2 — Restart the Orderer

kubectl rollout restart statefulset/orderer-0 -n i3-ford
kubectl rollout status statefulset/orderer-0 -n i3-ford
# Expected: statefulset rolling update complete

Step 3 — Generate the System Channel Genesis Block

# Using configtxgen (ensure configtx.yaml is populated with org MSP paths)
configtxgen \
  -profile FordOrdererGenesis \
  -channelID system-channel \
  -outputBlock ./genesis.block

# Copy genesis block into the orderer pod
kubectl cp ./genesis.block i3-ford/<orderer-pod>:/var/hyperledger/orderer/

Step 4 — Create Application Channels

# Create 'membership' channel
peer channel create \
  -o orderer-0.i3-ford.svc.cluster.local:7050 \
  -c membership \
  -f ./membership.tx \
  --tls --cafile $ORDERER_TLS_CA

# Peer joins the channel
peer channel join -b membership.block

# Repeat for 'nominations' and 'primaries-2027'

Step 5 — Package and Deploy Chaincode

# Package MembershipRegistry chaincode
peer lifecycle chaincode package membershipregistry.tar.gz \
  --path ./chaincode/MembershipRegistry \
  --lang node \
  --label membershipregistry_1

# Install on peer
peer lifecycle chaincode install membershipregistry.tar.gz

# Approve and commit (both orgs must approve)
peer lifecycle chaincode approveformyorg ...
peer lifecycle chaincode commit ...
⚠️ Multi-Org Endorsement All four chaincode packages require endorsement from both organisations (FORD org via ford-ca and i3Tech org via i3tech-ca). Coordinate approval calls between both org admins before committing each chaincode to a channel.

A11. Keycloak Client — Action Required

🚨 Action Required — ford-portal Client Secret Is Empty The Keycloak client ford-portal currently has an empty client secret. This means the FORD API cannot perform OIDC token introspection or service-account calls to Keycloak. This must be resolved before the portal goes live.

Remediation Steps

  1. Log in to the Keycloak admin console as realm administrator.
  2. Navigate to Clients → ford-portal → Credentials tab.
  3. Click Regenerate Secret. Copy the generated secret immediately.
  4. Store the secret in a Kubernetes Secret in the i3-ford namespace:
    kubectl create secret generic ford-keycloak-secret \
  --from-literal=client_secret=<regenerated_secret> \
  -n i3-ford
  5. Update the FORD API deployment to mount ford-keycloak-secret and reference it as the KEYCLOAK_CLIENT_SECRET environment variable.
  6. Restart the API deployment: kubectl rollout restart deployment/ford-api -n i3-ford.
  7. Test a login flow end-to-end: authenticate an agent via the portal and confirm the JWT is accepted by the API.

Part B — Field Agent User Guide

This section is written for FORD-Asili field registration agents. It explains your responsibilities, how to use the FORD Portal, and what to do when things go wrong. You do not need technical knowledge to follow this guide.

B1. Your Role as a Field Registration Agent

As a FORD-Asili Field Registration Agent, you are on the front line of building FORD-Asili's membership base ahead of the 2027 Kenya General Elections. Your job is to visit community members in your assigned ward, explain the FORD-Asili vision, and register willing members using the FORD Portal.

What You Are Responsible For

  • Visiting members in your assigned ward and registering them accurately.
  • Ensuring the member provides a valid National ID number and phone number.
  • Confirming the member's OTP code to complete registration (see Section B3).
  • Staying within your daily registration quota (50 members per day).
  • Never registering a member without their knowledge and consent.
🚨 Important Registering a person without their consent, or registering a fake person, is a criminal offence under Kenya's Elections Act. Your agent_id is permanently attached to every registration you make on the blockchain. Fraudulent registrations will be traced back to you.

Your Agent ID

You were given an Agent ID (e.g., AGT-00247) when your account was created. This ID is automatically attached to every member you register. It is used to track your performance and your daily registration count.

B2. Registering a New Member

Follow these steps carefully to register a new FORD-Asili member:

  1. Open the FORD Portal on your phone or laptop.
    Go to: https://ford.i3technologies.co.ke
  2. Log in using your agent username and password. If you have forgotten your password, contact your supervisor.
  3. Tap "Register New Member" on the dashboard.
  4. Fill in the member's details:
    • National ID Number (from their ID card — check carefully, no typos)
    • Phone Number (the number where they will receive an SMS — must be working)
    • Ward (your assigned ward — should be pre-filled)
    • Sub-County and County (should be pre-filled based on your profile)
  5. Tap "Submit Registration". The system will send an SMS OTP to the member's phone.
  6. Complete the OTP step — see Section B3 below.
✅ Tip: Double-check Before Submitting Read the National ID number and phone number back to the member before tapping Submit. A wrong ID number means the registration will be attached to the wrong person. There is no easy way to fix this after submission.

B3. The OTP Verification Process

OTP stands for One-Time Password. It is a 6-digit code sent by SMS to the member's phone number. This code proves that the phone number belongs to the member and that they are present and consenting.

What Happens

  1. After you submit the registration form, the FORD system sends an SMS to the member's phone. The SMS will say something like: "Your FORD-Asili verification code is 847291. Valid for 5 minutes."
  2. Ask the member to read out the 6-digit code from their SMS.
  3. Enter the 6-digit code into the "Verify OTP" box in the app and tap Confirm.
  4. If correct, you will see a green "Registration Successful" message. The member is now registered.

What If the SMS Does Not Arrive?

  • Wait up to 1 minute — SMS delivery can sometimes take a moment.
  • Check that the phone number entered was correct. Ask the member to confirm their number.
  • If the SMS still does not arrive after 2 minutes, tap "Resend OTP" if available, or cancel and re-submit the registration.
  • If the problem persists, note down the member's details and contact FORD support (Section B7).
⏱️ The OTP expires after 5 minutes. If the member does not enter the code within 5 minutes, it will expire. You will need to start the registration again. Make sure the member is ready with their phone before you submit.

B4. Understanding Your Duty Count

Your duty count shows how many members you have registered today. You can view it on the FORD Portal dashboard, or your supervisor can check it.

The Three Counts

CountWhat It Means
VerifiedMembers who completed OTP verification. These are fully registered.
PendingMembers who were submitted but have not yet verified their OTP. Follow up with them!
FlaggedRegistrations that were automatically flagged (see Section B5). These need admin review.

The 50-Per-Day Limit

You can register a maximum of 50 members per day. This limit resets every day at midnight. If you reach 50, the system will not allow any more registrations until the next day.

This limit exists to ensure quality and prevent errors. If you genuinely have more than 50 people waiting to register in a single day, speak to your supervisor who can request a temporary increase through the proper channels.

B5. What Happens When a Registration Is Flagged

A registration is automatically flagged by the system when it detects a potential problem — most commonly because the same National ID number has already been registered before.

Possible Reasons for Flagging

  • The member has already been registered by another agent.
  • The member has already registered themselves previously.
  • There was a data entry error and the same person was submitted twice.

What To Do

  • Tell the member the system has flagged their registration.
  • Do not try to register the same person again — it will flag again and may trigger a fraud alert on your account.
  • Record the member's name, the date, and the error message, and send this information to FORD support (Section B7).
  • An administrator will review the flagged record and either confirm the previous registration or clear the flag if it was an error.
⚠️ High Flag Rate = Investigation If your account shows many flagged registrations, FORD headquarters may investigate your activities. Always register members accurately and with their consent.
