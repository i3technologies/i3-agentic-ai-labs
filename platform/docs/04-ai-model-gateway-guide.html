1. Overview & Architecture

The AI & Model Gateway layer provides a unified, observable, and cost-tracked pathway to all AI inference. No application in the platform calls a model API directly — every request flows through LiteLLM, which routes to the correct backend (cloud providers or the local Ollama server) and records telemetry in Langfuse. Staff access AI via Sage (chat UI) or JupyterHub (notebooks). Embeddings and RAG data are stored in ChromaDB.

3.1 Admin Guide

Listing Loaded Models

# Via Ollama API (from inside the cluster or oc port-forward)
curl http://ollama.i3-ott.svc.cluster.local:11434/api/tags | jq .

# Via oc exec
oc exec -n i3-model-gateway ollama-0 -- ollama list

Pulling (Loading) a New Model

# General syntax
oc exec -n i3-model-gateway ollama-0 -- ollama pull MODEL_NAME

# Examples
oc exec -n i3-model-gateway ollama-0 -- ollama pull llama3:8b
oc exec -n i3-model-gateway ollama-0 -- ollama pull phi3:mini
oc exec -n i3-model-gateway ollama-0 -- ollama pull nomic-embed-text   # embedding model
Storage check before pulling The PVC is 80 GiB. Check available space with oc exec -n i3-model-gateway ollama-0 -- df -h /root/.ollama before pulling large models. A 13B Q4 model is ~8 GB; a 70B model is ~40 GB.

Removing a Model

oc exec -n i3-model-gateway ollama-0 -- ollama rm MODEL_NAME

Running an Ad-hoc Prompt (Testing)

oc exec -it -n i3-model-gateway ollama-0 -- \
  ollama run mistral:7b-instruct-q4_K_M "Explain Kubernetes in one sentence."

Checking Ollama Service Logs

oc logs -n i3-model-gateway ollama-0 --tail=100 -f

After Pulling a New Model — Register it in LiteLLM

Once a model is pulled into Ollama, add it to LiteLLM so apps can use it (see Section 2.1, Adding a New Model).

3.2 User Guide

End users do not call Ollama directly. Use LiteLLM (Section 2) or Sage (Section 4). The model mistral-7b in LiteLLM maps to mistral:7b-instruct-q4_K_M on Ollama.

For developers who need direct access during testing, forward the port:

oc port-forward -n i3-model-gateway svc/ollama 11434:11434 &

# Then call the Ollama API directly
curl http://localhost:11434/api/generate \
  -d '{
    "model": "mistral:7b-instruct-q4_K_M",
    "prompt": "What is the capital of Kenya?",
    "stream": false
  }' | jq .response

Selecting a Model

1
Click the model selector at the top of the chat window (shows the current model name).
2
All models registered in LiteLLM appear in the list. Choose the model appropriate for your task:
  • mistral-7b — fast, local, no data leaves the cluster. Use for internal documents.
  • gpt-4o — highest capability, uses OpenAI API (data leaves cluster).

Creating and Managing Conversations

  • Click New Chat (pencil icon) to start a fresh conversation.
  • Conversations are saved automatically and appear in the left sidebar.
  • Right-click a conversation to rename, pin, or delete it.
  • Use the search bar at the top of the sidebar to find past conversations.

Uploading Documents for RAG (Document Q&A)

1
Click the paperclip icon in the message input area.
2
Upload a PDF, DOCX, TXT, or CSV file (max 50 MB per file).
3
Sage chunks the document, embeds it via ChromaDB, and makes it available as context for your conversation.
4
Ask questions about the document content — the model retrieves relevant chunks before generating its answer.
Document privacy Uploaded documents are stored in ChromaDB within the cluster. If you are using a cloud model (e.g. gpt-4o), relevant chunks are sent to the external API. Use a local model (mistral-7b) for confidential documents.

Using System Prompts

Click the settings icon (⚙) on a conversation to set a custom system prompt. This is useful for persona-based interactions (e.g. "You are an HR assistant for i3 Technologies…").

4.2 Admin Guide

Adding a Model Connection

1
Log in with an admin account and go to Admin Panel → Settings → Connections.
2
Under OpenAI API, set the base URL to https://litellm.i3technologies.co.ke/v1 and the key to the LiteLLM master key (or a dedicated Sage key).
3
Click Verify Connection — Sage will fetch the model list from LiteLLM automatically.
4
New models pulled into Ollama and registered in LiteLLM will appear in Sage automatically after a page refresh.

Managing Users

  • Navigate to Admin Panel → Users to see all registered users.
  • Change a user's role (User / Admin) by clicking their name.
  • Disable an account by toggling the Active switch (account is not deleted, conversation history is preserved).
  • Use Admin Panel → Settings → Sign Up to control whether self-registration is allowed or invite-only.

Managing Knowledge Bases

Shared document collections (knowledge bases) can be created under Workspace → Knowledge and made available to all users or specific groups. This is useful for company policies, technical docs, and SOPs.

Viewing Traces

Filtering Traces by Application

Cost Reports

  • Export as CSV with the Export button for budget reporting.
  • Token usage trends are available under Analytics → Usage.
