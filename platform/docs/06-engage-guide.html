1. Overview

i3 Engage is the unified communication hub of the i3 platform. It consolidates outbound and inbound messaging across three channels — WhatsApp Business API, SMS (Africa's Talking), and Email (Brevo) — into a single operator dashboard, event-driven automation engine, and API surface used by every other platform component.

AttributeValue
Dashboard URLhttps://engage.i3technologies.co.ke
WhatsApp Webhookhttps://engage-webhook.i3technologies.co.ke/webhook/whatsapp
Kubernetes Namespacei3-engage
AI CoworkerNuru AI — https://nuru.i3technologies.co.ke
Messaging ChannelsWhatsApp · SMS · Email
AuthKeycloak SSO (client: engage-web)

Channels & Use Cases

ChannelProviderPrimary Use Cases
WhatsApp Meta Business API Customer notifications, order confirmations, support conversations, Nuru AI bot responses
SMS Africa's Talking OTP delivery, alert broadcasts, fallback channel when WhatsApp unavailable
Email Brevo (SMTP + API) Transactional emails, reports, onboarding flows, campaign newsletters

Platform Integration Points

  • n8n — Engage fires webhook events that trigger n8n workflows; n8n also calls the Engage API to send messages from automation flows.
  • Kafka — All inbound and outbound message events are published to the Kafka event bus for downstream consumers (analytics, AI, audit).
  • Platform apps — Any i3 component (iShop, iTrack, iLearn, etc.) can call the Engage REST API to send contextual messages to users.
  • ChromaDB — Conversation embeddings are stored in ChromaDB for Nuru AI semantic retrieval and context management.

3. Configuring the WhatsApp Webhook

Engage receives inbound WhatsApp messages and delivery receipts through a Meta-verified webhook endpoint. Use the following URL when registering in Meta Business Manager:

https://engage-webhook.i3technologies.co.ke/webhook/whatsapp

Step-by-Step Setup in Meta Business Manager

  1. Log in to Meta Business Manager at business.facebook.com using the account linked to the i3 WhatsApp Business number.
  2. Navigate to Business Settings → WhatsApp Accounts → [Your Account] → Configuration.
  3. Under Webhook, click Edit and paste the webhook URL above into the Callback URL field.
  4. Set the Verify Token to the value stored in the Engage deployment secret engage-secrets/WHATSAPP_VERIFY_TOKEN. Retrieve it with: 
    kubectl get secret engage-secrets -n i3-engage \
  -o jsonpath='{.data.WHATSAPP_VERIFY_TOKEN}' | base64 -d
  5. Click Verify and Save. Meta will send a GET challenge to the webhook; Engage will respond automatically.
  6. Subscribe to the following webhook fields: messages, message_deliveries, message_reads, messaging_postbacks.
  7. Confirm the green Active badge appears next to the webhook URL in Business Manager.

Testing the Webhook

# Send a test verification challenge manually
curl -X GET "https://engage-webhook.i3technologies.co.ke/webhook/whatsapp\
?hub.mode=subscribe\
&hub.verify_token=YOUR_VERIFY_TOKEN\
&hub.challenge=test123"

# Expected response: test123
💡 Tip Webhook logs are streamed to the Engage pod. To tail in real time: kubectl logs -f deploy/engage-webhook -n i3-engage

4. Configuring Africa's Talking for SMS

🔴 Action Required Africa's Talking credentials are currently set to placeholder values. SMS messages will not be delivered until you complete the steps below.

Obtaining Your Credentials

  1. Log in to the Africa's Talking dashboard at account.africastalking.com.
  2. Go to Settings → API Key — copy the production API key.
  3. Your username is shown at the top-right of the dashboard (typically your registered account name, e.g., i3technologies).

Applying the Credentials to the Cluster

# Patch the Kubernetes secret
kubectl patch secret engage-secrets -n i3-engage \
  --type='json' \
  -p='[
    {"op":"replace","path":"/data/AT_API_KEY",
     "value":"'$(echo -n "YOUR_ACTUAL_API_KEY" | base64)'"},
    {"op":"replace","path":"/data/AT_USERNAME",
     "value":"'$(echo -n "YOUR_ACTUAL_USERNAME" | base64)'"}
  ]'

# Restart the Engage deployment to pick up the new secret
kubectl rollout restart deployment/engage-api -n i3-engage
kubectl rollout status deployment/engage-api -n i3-engage
Sandbox vs Production Africa's Talking provides a sandbox environment (username: sandbox, test API key) for development. Switch to production credentials before going live. The Engage configuration key AT_ENVIRONMENT should be set to production for live traffic.

Verifying SMS Delivery

  1. From the Engage dashboard → Send Message → select SMS channel.
  2. Enter a valid Kenyan mobile number (format: +2547XXXXXXXX).
  3. Click Send and observe the delivery status in Message Logs.
  4. Cross-check delivery receipts in the Africa's Talking dashboard under SMS → Outbox.

6. Creating Message Templates

Templates define reusable message structures with variable placeholders ({{1}}, {{2}}, …). WhatsApp templates must additionally be approved by Meta before they can be used in business-initiated conversations.

WhatsApp Template Requirements

  • Templates are created in Meta Business Manager → WhatsApp → Message Templates.
  • Categories: Marketing, Utility, or Authentication.
  • Approval typically takes 24–48 hours. Status is visible in Business Manager.
  • Approved template names must then be registered in the Engage Templates section so the platform knows which template maps to which event.

Creating an Engage Template (Dashboard)

  1. Navigate to Engage → Templates → New Template.
  2. Choose the channel: WhatsApp, SMS, or Email.
  3. For WhatsApp: enter the Template Name exactly as approved in Meta Business Manager. Select the language code (e.g., en_US).
  4. Define the Body with variable placeholders: Hello {{1}}, your order {{2}} is confirmed.
  5. For Email: fill in Subject, HTML Body, and optionally a Plain-text fallback.
  6. Assign a Template Key (snake_case identifier used by other platform components when calling the Engage API).
  7. Click Save & Activate. The template is immediately available for use.

Calling a Template from the API

POST https://engage.i3technologies.co.ke/api/v1/messages/send
Authorization: Bearer <JWT>

{
  "channel": "whatsapp",
  "to": "+254700000000",
  "template_key": "order_confirmed",
  "variables": ["John", "ORD-9921"]
}

7. Message Logs & Analytics

Viewing Logs in the Dashboard

  1. Go to Engage → Logs. The default view shows the last 24 hours across all channels.
  2. Use the filters: Channel, Status (sent / delivered / failed / read), Date Range, and Contact.
  3. Click any log row to expand the full message payload, delivery timestamps, and any provider error codes.
  4. Export logs as CSV using the Export button (top-right of the logs table).

Key Status Codes

StatusMeaning
queuedMessage accepted, waiting for provider submission
sentSubmitted to provider; not yet confirmed at device
deliveredConfirmed delivery to recipient device
readRecipient opened the message (WhatsApp only)
failedProvider rejected or could not deliver; check error_code

Analytics Dashboard

Navigate to Engage → Analytics for aggregated metrics: delivery rates by channel, hourly message volume, template performance, and error rate trends. Data is sourced from Kafka consumer offsets and refreshed every 5 minutes.

8. n8n Integration

i3 Engage and n8n form a bidirectional automation bridge:

  • Engage → n8n: Engage publishes webhook events when messages are received, delivered, or fail — n8n listens via its Webhook trigger node and executes downstream workflow logic.
  • n8n → Engage: n8n workflows call the Engage REST API (with a service-account JWT) to send messages as part of multi-step automations.

Registering an n8n Webhook Listener

  1. In n8n, create a new workflow and add a Webhook trigger node.
  2. Copy the generated Webhook URL from n8n (e.g., https://n8n.i3technologies.co.ke/webhook/xxxxxxxx).
  3. In Engage → Settings → Webhook Subscriptions → Add Subscription, paste the n8n URL.
  4. Select the event types to forward: message.received, message.delivered, message.failed, conversation.started.
  5. Set a Secret Header (HMAC-SHA256) that n8n will use to verify payloads. Store this in n8n as a credential.
  6. Save and Test Delivery — Engage will POST a sample payload to the n8n URL.

Engage Event Payload Shape

{
  "event": "message.received",
  "timestamp": "2026-01-15T09:00:00Z",
  "channel": "whatsapp",
  "contact": { "phone": "+254700000000", "name": "Jane Doe" },
  "message": {
    "id": "wamid.XXXX",
    "type": "text",
    "body": "Hello, I need help with my order.",
    "media_url": null
  }
}

9. Kafka Topics

Engage produces and consumes events on the shared Kafka bus at kafka-bootstrap.i3-messaging.svc.cluster.local:9092.

TopicDirectionDescription
engage.messages.outbound Producer All outbound message events (sent/failed) for downstream analytics and audit
engage.messages.inbound Producer All inbound WhatsApp/SMS messages received by Engage

10. Nuru AI Coworker

Nuru AI (https://nuru.i3technologies.co.ke) is the i3 platform's WhatsApp AI assistant. It operates as a coworker to Engage: inbound WhatsApp messages routed to Nuru are processed through its LLM pipeline, with conversation context retrieved from ChromaDB, and responses dispatched back through Engage.

Architecture

  • Engage receives a WhatsApp inbound message and publishes it to engage.messages.inbound.
  • Nuru AI consumes the event, performs retrieval-augmented generation (RAG) against ChromaDB, and emits a response to nuru.ai.events.
  • Engage consumes nuru.ai.events and sends the AI response back to the original WhatsApp sender.
  • Full conversation thread is stored as embeddings in ChromaDB (collection: nuru_conversations).

Part B — User Guide Sections 12 – 17

12. Accessing the Engage Dashboard

  1. Open your browser and navigate to https://engage.i3technologies.co.ke.
  2. You will be redirected to the Keycloak login page. Enter your i3 platform username and password.
  3. On first login, you may be prompted to set up two-factor authentication — follow the on-screen instructions.
  4. After authentication you land on the Engage Home Dashboard, which displays:
    • Message volume summary (last 24 h) by channel
    • Recent conversations feed
    • Quick-send widget
    • Active automation status
  5. Use the left navigation to switch between Inbox, Contacts, Templates, Automation, Logs, and Analytics.
Role-based Access Your dashboard view may differ depending on your role: Agent sees only their assigned conversations; Supervisor sees team-wide inboxes; Admin has access to all settings and configuration panels.

13. Sending a Manual Message

Quick Send (Single Recipient)

  1. Click the Compose button (pencil icon) in the top-right of the dashboard, or navigate to Inbox → New Conversation.
  2. In the To field, type a phone number (WhatsApp/SMS: +2547XXXXXXXX) or email address. The system will auto-suggest existing contacts.
  3. Select the Channel: WhatsApp, SMS, or Email.
  4. For WhatsApp, if no open conversation exists with this contact, you must select an approved Template to initiate the conversation (Meta policy). Once the contact replies, you may send free-form messages for 24 hours.
  5. For SMS and Email, type your message directly in the body field. For Email, fill in the Subject line as well.
  6. Attach files if needed (WhatsApp and Email support attachments; SMS does not).
  7. Click Send. A confirmation toast will appear and the conversation is added to your Inbox.

Bulk Message (Broadcast)

  1. Go to Contacts → Broadcast.
  2. Select a Contact List or apply filters (tag, segment, last-active date).
  3. Choose a Template and map variable fields to contact attributes (e.g., {{1}} → First Name).
  4. Review the recipient count and preview a sample message.
  5. Click Schedule (to send later) or Send Now. Monitor delivery in Logs → Broadcast.

14. Managing Contact Lists

Adding a Contact

  1. Navigate to Contacts → New Contact.
  2. Fill in: Full Name, Phone (required for WhatsApp/SMS), Email (required for email channel), and any custom attributes.
  3. Assign one or more Tags (e.g., vip, supplier, student) for segmentation.
  4. Click Save Contact.

Importing Contacts (CSV)

  1. Go to Contacts → Import.
  2. Download the CSV template and fill in your contact data.
  3. Required columns: name, phone. Optional: email, tags.
  4. Upload the completed CSV. Engage will validate and show a preview with any error rows highlighted.
  5. Click Confirm Import. Duplicates (matched on phone number) are automatically merged.

Segmenting Contacts

Use Contacts → Segments to create dynamic groups based on filter rules (e.g., tag = student AND last_message > 30 days ago). Segments update automatically as contact data changes and can be used directly as broadcast targets.

15. Viewing Conversation History

  1. Go to Inbox. Use the channel filter tabs (All / WhatsApp / SMS / Email) and status filters (Open / Pending / Resolved).
  2. Click any conversation to open the thread view. The full message history is displayed in chronological order with timestamps and delivery indicators.
  3. To search across all conversations, use the global Search bar (magnifier icon, top navigation). Search by contact name, phone number, message content, or template used.
  4. To view a specific contact's complete history across all channels, open Contacts → [Contact Name] → Conversation History.
  5. To export a conversation, open it and click ⋯ → Export as PDF or Export as CSV.
Conversation Assignment Conversations can be assigned to specific agents via the Assign button in the thread view. Assigned conversations appear in the agent's personal My Conversations queue.

16. Setting Up Automated Responses

Auto-Reply Rules

  1. Navigate to Automation → Rules → New Rule.
  2. Set the Trigger: e.g., Message Received, Keyword Match (hello, hi), or Business Hours (outside working hours).
  3. Set the Condition: channel, contact tag, time of day, etc.
  4. Set the Action: Send Template Message, Assign to Agent, Add Tag, or Trigger n8n Webhook.
  5. Toggle the rule to Active and click Save.

Out-of-Office / Business Hours Reply

  1. Go to Settings → Business Hours and configure your working hours and timezone.
  2. In Automation → Rules, create a rule: Trigger = Message Received, Condition = Outside Business Hours, Action = Send Template Message (select an appropriate out-of-office template).

Keyword-Based Routing

Use keyword triggers to route conversations to the right team. Example: a message containing "invoice" or "payment" → assign to Finance Team inbox. Add multiple keywords in the rule by separating with commas.

17. Using the Nuru AI Assistant

Nuru AI is an AI-powered WhatsApp assistant accessible at https://nuru.i3technologies.co.ke. From the operator perspective, Nuru can handle conversations autonomously and hand off to human agents when needed.

Triggering Nuru AI

  • Automatic routing: Messages to the Nuru-designated WhatsApp number are handled by AI by default.
  • Manual assignment: Inside any conversation, click ⋯ → Assign to Nuru AI to hand off the conversation to the AI assistant.
  • Keyword trigger: If a user sends !nuru in a conversation, Nuru AI takes over automatically.

Monitoring AI Conversations

  1. Go to Inbox → Filter → Handled by AI to see all Nuru-managed conversations.
  2. Each conversation shows an AI badge. You can read the full dialogue including AI-generated responses.
  3. If an AI response is unsatisfactory, click Take Over to reassign the conversation to a human agent. Nuru will stop responding to that thread.
  4. Nuru confidence scores (low/medium/high) are shown per message. Conversations with low-confidence responses are automatically flagged for review in the Review Queue.

Training & Feedback

  • Use the 👍 / 👎 feedback buttons on AI messages to signal response quality. Feedback is logged and used to refine the model.
  • Add frequently asked questions and their answers in Nuru AI → Knowledge Base to improve response accuracy for recurring queries.
  • Embed new documents (PDFs, product guides) via Nuru AI → Upload Document — these are indexed into ChromaDB for RAG retrieval.
Context Window Nuru retrieves the last 10 messages of each conversation thread plus semantically similar past interactions from ChromaDB to maintain context. Long-dormant conversations (> 7 days) start with a fresh context window.
