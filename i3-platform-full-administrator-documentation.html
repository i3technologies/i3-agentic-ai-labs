Cluster: i3-platform  ·  Provider: IBM ROKS 4.17 (OpenShift), eu-de (Frankfurt)  ·  Nodes: 12 × bx2.4x16 (4 vCPU / 16 GB each) = 48 vCPU / 192 GB RAM  ·  Version: v3.0  ·  Date: September 2026  ·  Audience: Sebastian Njagi, Philip Mukiti, Joseph Maina

1 · Platform Overview

Core Mandate: A fully commercialisable, 100% open-source AI platform on IBM ROKS compute. IBM Credits cover compute only — all AI inference runs on-cluster via Ollama (CPU-quantised GGUF). No GPU nodes. No watsonx SaaS. The platform serves: (1) i3 internal operations, (2) six commercial AI products, (3) training — Bootcamps, Hackathons, Agentic AI Summit.
Critical boundary: Namespaces solution-01 through solution-08 contain customer solutions on a SEPARATE server. They are NEVER touched by this pipeline. Do not apply manifests, scale, or delete anything in those namespaces.

Common Admin Tasks

# Get admin token
KC_TOKEN=$(curl -s https://auth.i3technologies.co.ke/realms/master/protocol/openid-connect/token \
  -d "client_id=admin-cli&grant_type=password&username=admin&password=$KC_ADMIN_PW" \
  | jq -r .access_token)

# List users in i3 realm
curl -s -H "Authorization: Bearer $KC_TOKEN" \
  https://auth.i3technologies.co.ke/admin/realms/i3/users | jq '.[].username'

# Create a new user
curl -s -X POST -H "Authorization: Bearer $KC_TOKEN" \
  -H "Content-Type: application/json" \
  https://auth.i3technologies.co.ke/admin/realms/i3/users \
  -d '{"username":"newuser@example.com","email":"newuser@example.com","enabled":true,"emailVerified":true}'

# Reset user password
USER_ID=$(curl -s -H "Authorization: Bearer $KC_TOKEN" \
  "https://auth.i3technologies.co.ke/admin/realms/i3/users?email=user@example.com" | jq -r '.[0].id')
curl -s -X PUT -H "Authorization: Bearer $KC_TOKEN" \
  -H "Content-Type: application/json" \
  "https://auth.i3technologies.co.ke/admin/realms/i3/users/$USER_ID/reset-password" \
  -d '{"type":"password","value":"TempPass123!","temporary":true}'

# Force JWKS refresh after key rotation
curl -sk https://auth.i3technologies.co.ke/realms/i3/protocol/openid-connect/certs | jq .

# In Keycloak Admin Console: Users → [user] → Attributes → add  isAdmin = true

7 · OpenBao Vault (Secrets Management)

Namespacei3-security
Topology3-node HA StatefulSet · Shamir threshold 3-of-5
Auth methodsKubernetes (for pods) · Userpass (for admins)
UIhttps://vault.i3technologies.co.ke (Keycloak-gated)
⚠ Unseal keys & root token: Store the output of bao operator init in your offline HSM or paper vault. NEVER commit to git. NEVER store in Slack or email. These keys are irrecoverable if lost.

Bootstrap (One-Time)

# Deploy OpenBao StatefulSet
oc apply -f platform/operators/openbao/openbao-deploy.yaml
oc rollout status statefulset/openbao -n i3-security

# Initialize (3-of-5 Shamir)
oc exec -n i3-security openbao-0 -- bao operator init \
  -key-shares=5 -key-threshold=3 \
  -format=json > /tmp/openbao-init.json
# ⚠ Immediately store /tmp/openbao-init.json offline

# Unseal all 3 nodes (each needs 3 different key shares)
for pod in openbao-0 openbao-1 openbao-2; do
  for key in $(cat /tmp/openbao-init.json | jq -r '.unseal_keys_b64[:3][]'); do
    oc exec -n i3-security $pod -- bao operator unseal $key
  done
done

# Bootstrap policies + K8s auth via Ansible Job
ROOT_TOKEN=$(cat /tmp/openbao-init.json | jq -r '.root_token')
oc create secret generic openbao-root-token -n i3-security \
  --from-literal=token=$ROOT_TOKEN
oc apply -f platform/operators/openbao/openbao-bootstrap-job.yaml
oc wait --for=condition=complete job/openbao-bootstrap -n i3-security --timeout=5m

# Revoke root token (security hardening)
oc exec -n i3-security openbao-0 -- bao token revoke $ROOT_TOKEN
oc delete secret openbao-root-token -n i3-security

Daily Unseal (after pod restart)

# Check seal status
oc exec -n i3-security openbao-0 -- bao status

# Unseal if sealed (requires 3 key holders to each run once)
oc exec -n i3-security openbao-0 -- bao operator unseal <key-share-N>

# Describe pod for events
oc describe pod <pod-name> -n <namespace>

# OOMKilled — increase memory limit
oc patch deployment <name> -n <ns> \
  --type=merge -p '{"spec":{"template":{"spec":{"containers":[{"name":"<c>","resources":{"limits":{"memory":"4Gi"}}}]}}}}'

# Delete stuck pod (will be recreated by Deployment)
