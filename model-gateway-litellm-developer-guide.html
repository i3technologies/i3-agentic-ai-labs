1. What is the Model Gateway?

The i3 Model Gateway is a centralised LiteLLM proxy that routes all AI model calls from platform services. It provides a single, OpenAI-compatible API endpoint for all models — Qwen, Granite, LLaVA, and embedding models — with automatic fallback routing, Redis semantic caching, per-key budget enforcement, and full observability via Langfuse and Prometheus.

Architecture Rule R1: ALL model calls across the i3 platform must go through this gateway. Direct calls to Ollama, vLLM, or any model endpoint are forbidden. No exceptions.

2. Getting Access

1

Request a Service API Key

Contact your platform administrator or submit a request via the Agent Registry. Specify: your service name, tenant ID, required model tiers, and estimated daily token usage.

2

Receive Your Virtual Key

Your per-service virtual key is provisioned via the Agent Registry and injected into your service via OpenBao. The key has a budget limit and is scoped to your tenant. You will also receive the gateway URL.

3

Test Connectivity

Verify access with a simple chat completion call (see Section 3).

Master key policy: The master LiteLLM key is a break-glass credential stored in OpenBao. You must NEVER use it for development, testing, or service integration. Always use your per-service virtual key.

3. Making Your First API Call

Using the OpenAI Python SDK

from openai import OpenAI

client = OpenAI(
    api_key="sk-your-service-virtual-key",
    base_url="https://model-gateway.i3technologies.co.ke/v1"
)

response = client.chat.completions.create(
    model="qwen-fast",
    messages=[
        {"role": "user", "content": "What is the capital of Kenya?"}
    ]
)
print(response.choices[0].message.content)

Using curl

curl https://model-gateway.i3technologies.co.ke/v1/chat/completions \
  -H "Authorization: Bearer sk-your-service-virtual-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-fast",
    "messages": [
      {"role": "user", "content": "What is the capital of Kenya?"}
    ]
  }'

5. Automatic Fallback Chain

The gateway automatically retries on model timeout or error using the configured fallback chain. Your code does not need to handle fallbacks — the gateway manages this transparently.

qwen-heavy  ──(fail/timeout)──▶  qwen-fast  ──(fail/timeout)──▶  granite-nano (terminal)
qwen-fast   ──(fail/timeout)──▶  granite-nano (terminal)
qwen-coder  ──(fail/timeout)──▶  qwen-fast
vision      ──(fail/timeout)──▶  qwen-heavy
Tip: If granite-nano is returned for a request that should use qwen-heavy, check Langfuse — this indicates qwen-heavy and qwen-fast are both unavailable. Alert your admin.

6. Semantic Cache

The gateway maintains a Redis semantic cache. Requests with a prompt similarity ≥ 0.95 (cosine similarity to a cached request) are served from cache — no model call needed.

Cache behaviour from the client's perspective

  • Cache hits return instantly (<100ms) and consume zero tokens.
  • The response looks identical to a normal model response.
  • Cache TTL is 1 hour (3600 seconds). After expiry, the next identical request triggers a fresh model call.
  • Cache is shared across all services using the same gateway — a cached answer from PMaaS benefits Admissions and vice versa for similar prompts.

When cache is NOT used

  • Streaming requests (stream: true)
  • Requests with unique dynamic context (user-specific data)
  • Requests where similarity to any cached entry is < 0.95

7. Generating Text Embeddings

from openai import OpenAI

client = OpenAI(
    api_key="sk-your-service-virtual-key",
    base_url="https://model-gateway.i3technologies.co.ke/v1"
)

response = client.embeddings.create(
    model="embed-nomic",
    input="Sample document text to embed for vector search"
)

embedding_vector = response.data[0].embedding
print(f"Embedding dimensions: {len(embedding_vector)}")

8. Streaming Responses

from openai import OpenAI

client = OpenAI(
    api_key="sk-your-service-virtual-key",
    base_url="https://model-gateway.i3technologies.co.ke/v1"
)

stream = client.chat.completions.create(
    model="qwen-fast",
    messages=[{"role": "user", "content": "Write a campaign speech for Machakos."}],
    stream=True
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)

9. Monitoring Your Usage (Langfuse)

Every model call is automatically traced in Langfuse. To view your service's traces:

  1. Request Langfuse access from your administrator (project-scoped viewer role).
  2. Log in to the Langfuse dashboard.
  3. Filter traces by your service-name tag or your virtual key's project ID.
  4. View: model used, prompt tokens, completion tokens, latency, cache hit/miss, cost.
  5. Use RAGAS score tab to view AI quality metrics for RAG pipeline traces.

Key Metrics to Monitor

Cache hit rateLangfuse / PrometheusBelow 30% for repetitive workloads
Fallback ratePrometheus litellm_fallback_totalAbove 5% sustained
P95 latencyLangfuse tracesAbove model timeout threshold

Error ratePrometheusAbove 1% of requests

10. Budget & Quota Management

  • Each virtual key has a configurable daily token budget.
  • When a key exceeds its budget, requests are rejected with HTTP 429 Too Many Requests.
  • Budget resets at midnight UTC each day.
  • To request a budget increase, contact your platform administrator with your daily usage metrics from Langfuse.
# Handling budget exhaustion in your code
try:
    response = client.chat.completions.create(
        model="qwen-fast",
        messages=[{"role": "user", "content": prompt}]
    )
except Exception as e:
    if "429" in str(e):
        # Budget exceeded — fall back to local processing or queue for next day
        print("Model gateway budget exceeded for today. Request queued.")
    else:
        raise
