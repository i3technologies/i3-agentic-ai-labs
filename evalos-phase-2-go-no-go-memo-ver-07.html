Blocking Findings

BLOCKER-1 · U-09 / ADR-006 · Lobster Trap NOT implemented on Zuri

Zuri is an Open WebUI deployment. ADR-006 (status: Proposed) mandates guard_input() on user_message, question, and context fields before LLM prompt assembly. No custom middleware, no filter function, no equivalent pattern found anywhere in platform/evalos/ or platform/evalos/web/src/. Zuri currently routes every user chat message directly to LiteLLM with no injection screening. HC-3 is violated.

Resolution: Open WebUI supports WEBUI_CHAT_FILTER_URL — deploy a FastAPI sidecar implementing the 12-pattern guard_input() function from ADR-006 §Implementation, and wire it as the OpenWebUI chat filter. Alternatively, place an Envoy Lua filter at the ingress. ADR-006 must move to Accepted status with evidence of implementation. Estimated effort: 1 sprint (2 days implement + 1 day test).

BLOCKER-2 · U-06 · evalos-submissions Kafka producer missing in EvalOS Web

The consumer (run_evalos_submissions_consumer() in platform/engage/consumers/platform_event_consumers.py) is implemented and correct — it parses CloudEvent envelopes, enforces HC-4 tenant_id, and triggers the grading pipeline. However, no Kafka producer exists in the EvalOS Web submit route. platform/evalos/web/src/app/api/exam/[examId]/submit/route.ts calls the grading-service directly via HTTP. The topic evalos-submissions (6 partitions, 30-day retention) is provisioned but will never receive messages. The consumer group evalos-submissions-grading will show zero lag — a silent no-op.

Resolution: Add a Kafka produce call after SAGA Step 4 in submit/route.ts using kafkajs (already in the monorepo lock file). Emit a i3.evalos.submission.received CloudEvent with the 9-field envelope (tenantid, subject_id_hash, attempt_id, exam_id). This also decouples the synchronous HTTP grading call so that slow grading does not block the HTTP response. Estimated effort: 0.5 days.

BLOCKER-3 · P2-GATE-02 / HC-3 · Agent Registry has only 1/6 manifests seeded

platform/agent-registry/manifests/ contains only admissions-agent-v1.yaml. The ADR-002 decision (status: Proposed) requires 6 manifests: Admissions Agent, Campaign Agent, Onboarding Agent, EvalOS Zuri, PMaaS Agent, FORD Election Agent. Without these manifests: (a) the MCP gateway cannot validate Zuri's allowed_tools list; (b) HC-3 compliance is unauditable for 5 of 6 agents; (c) P2-GATE-02 sensor will fail at exit gate review.

Resolution: Author 5 manifest YAML files following the schema in admissions-agent-v1.yaml. Zuri manifest must declare autonomy_level: L1 and reference the Lobster Trap sidecar once BLOCKER-1 is resolved. No manifest may declare autonomy_level: L2 or L3 without verified evaluation evidence per HC-3. Estimated effort: 1 day.

Non-Blocking Warnings

WARN-1 · HC-4 / DDL gap · 4 EvalOS tables missing tenant_id in schema.sql

Migration 005_add_tenant_id.sql covers 8 tables correctly. However, the canonical platform/evalos/schema.sql defines 4 additional tables — code_submissions, ai_interviews, question_sets, enrolment_queue — that have no tenant_id column and no RLS policy. These tables are not blocked for Phase 2 if they hold no per-student sensitive data at launch, but must be migrated before any multi-tenant student data is written to them. Recommend treating as blocking for P3-GATE.

WARN-2 · admin/generate-questions · LLM input from admin user not Lobster Trap guarded

platform/evalos/web/src/app/api/admin/generate-questions/route.ts passes topic and domain fields — admin-supplied strings — directly into the LLM prompt without firewall screening. Admin users are authenticated and role-gated (isAdmin: true), reducing the attack surface, but insider threat and account compromise are not mitigated. Add lobsterTrap(topic) and lobsterTrap(domain) guards before buildGenerationPrompt().

WARN-3 · interview/evaluate · studentAnswer not firewall-guarded

platform/evalos/web/src/app/api/interview/evaluate/route.ts interpolates studentAnswer directly into buildTextEvalPrompt() with no Lobster Trap check. A student can craft an answer that attempts to override the evaluator's scoring rubric. Firewall guard must be added as part of the U-09 resolution.

WARN-4 · Vault placeholders · REPLACE_FROM_VAULT in deployed secrets

zuri-deploy.yaml and evalos-deploy.yaml carry literal REPLACE_FROM_VAULT and REPLACE_WITH_* strings. The OpenBao agent-inject annotation is present, so the sidecar should overwrite these at pod startup — but this has not been verified at runtime. The P2-GATE-11 sensor (grep "REPLACE_FROM_VAULT" platform/admissions/admissions-deploy.yaml → 0 matches) is not yet run against EvalOS deploy manifests. Recommend adding EvalOS to the REPLACE_FROM_VAULT grep sweep before production deployment.
