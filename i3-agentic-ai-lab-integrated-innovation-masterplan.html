Upgrade 3 — Port Lobster Trap firewall from Python to TypeScript
// src/security/lobster-trap.ts
// Direct port of platform/admissions/admissions_agent.py TRAP_PATTERNS
const TRAP_PATTERNS = [
  /ignore\s+(all\s+)?previous\s+instructions?/i,
  /you\s+are\s+now\s+(?!an?\s+(onboarding|platform))/i,
  /act\s+as\s+(?!an?\s+(onboarding|platform))/i,
  /system\s*(prompt|message|instruction)/i,
  /jailbreak/i,
  /DAN\s+mode/i,
  /(drop|delete|truncate)\s+table/i,
  /SELECT\s+.*FROM\s+/i,
];

export function lobsterTrap(text: string): string | null {
  for (const pattern of TRAP_PATTERNS) {
    if (pattern.test(text)) return pattern.source;
  }
  return null;
}

export async function evalosSubagent(role: string, evalosApiKey: string): Promise<ScanResult> {
  // Query the EvalOS API for exam domains and question distribution
  // Use this to generate onboarding tasks like:

Five Innovation Edges — Judge Wow Factor
Innovation 1 — Live Platform as the Seed Repo (No Fake Data)
Instead of a fabricated three-module repo, ingest the actual i3 production platform: 12 namespaces, 6 databases, real Tekton pipelines, real Python agents, real Terraform, real RUNBOOK.md. When the verification loop flags "RHOAI (Month 3) not yet deployed — tasks referencing i3-ai-lab namespace are verified: false", this is a real catch on a real stale doc — not a staged demonstration. This is unfakeable.
Innovation 2 — Skill-Adaptive Personalization (Seniority-Aware Paths)
The skills-assessor.ts probe (5 questions, 90 seconds) determines whether the new hire gets the Bootcamp Student path (start with EvalOS practice quiz + Jupyter notebook tutorial), the Platform Engineer path (start with RUNBOOK.md + Tekton walkthrough), or the AI/ML Engineer path (start with LiteLLM API call + admissions agent code review). Same agent. Three entirely different first weeks. This is what separates an intelligent onboarding system from a static checklist.
Innovation 3 — EvalOS-Calibrated Learning Tasks
The evalos-scan subagent queries the live EvalOS question bank and maps exam domain weights (Agent Integration 38%, Platform Architecture 24%, etc.) to weekly learning tasks. A generated task might read: "Complete EvalOS practice domain: Agent Integration & Development — this is 38% of the IBM C1000-207 exam. Start with the 10-question drill at evalos.i3technologies.co.ke before Week 3." The task is verified against the live EvalOS API. If the domain exam has no questions yet, it is flagged verified: false automatically.
Innovation 4 — Langfuse Live Observability as Demo Screen
During the demo, open langfuse.i3technologies.co.ke on a second screen. As the agent runs, judges watch 5 subagents completing in parallel in real time — each with model name, token count, cost, and latency visible. This transforms an abstract "subagents run concurrently" claim into a live, auditable proof visible to the entire room. Screenshot becomes the submission evidence artifact.
Innovation 5 — n8n Auto-Trigger: Zero-Touch Onboarding
Wire an n8n workflow: EvalOS enrolment assessment passed → auto-enrolment webhook fires → onboarding agent generates personalized plan → plan emailed to student within 5 minutes. The student receives a tailored first-week plan before they have even logged into the platform for the first time. Demo beat: enrol a test user live, show the email arriving with their personalized plan — the agent ran entirely autonomously without a human clicking anything.

Cross-Platform Synergies
Synergy with Project 7 — Interactive Onboarding Chatbot

Project 7 (Interactive Onboarding Chatbot) shares the same ChromaDB context store and the same confidence gate pattern. If both are built, Project 1 generates the structured plan and Project 7 provides the conversational layer on top of it. The shared onboarding-corpus collection means both agents are grounded in identical platform knowledge — no re-ingestion needed. The Shared Context Bus pattern from the cross-project recommendations already applies here.

Synergy with EvalOS — Closed Feedback Loop

After a student completes Week 1 tasks, EvalOS exam scores feed back into the onboarding agent via Kafka topic evalos-submissions. The agent can detect "student scored 45% on Agent Integration domain" and automatically update the week 2 plan to add remediation tasks. This is the AI-Augmented Learning Loop described in the Master Technical Implementation Guide §6.6.1 — and it runs entirely within the existing platform infrastructure.

Synergy with PMaaS 4.0 — Commercial Vertical Extension
Commercial Extension: Campaign Staff Onboarding PMaaS 4.0 deploys for the Kenya 2027 elections across 1,882 seats. Every campaign hires ward-level agents, data analysts, and community coordinators who need to understand the voter database structure, the ward-level intelligence data model, and the campaign's policy positions — fast. The same onboarding agent, pointed at the PMaaS 4.0 manifesto corpus and ward intelligence docs, generates role-specific campaign-staff ramp-up plans. This is a direct commercial extension of the hackathon build with zero architectural changes.
Synergy with the 12-Week Bootcamp — Week 9 Lab Material

The onboarding agent itself becomes the Week 9 "Multi-Agent Coordination" lab exercise. Students extend it: add a new subagent, wire a new corpus source, improve the confidence scoring. The agent is both the product of the hackathon and the teaching material for the next cohort. This is the most powerful self-reinforcing loop in the entire platform.

Synergy with LLM Wiki (LLM Corporate Second Brain)

The LLM Wiki pattern from the Master Guide (§4.1) — structured raw/ → wiki/ → instructions/ Markdown repository — is the perfect permanent home for onboarding corpus content. Platform documentation ingested by the agent can be automatically linted and written back to the LLM Wiki via the Kiro postToolUse hook. Onboarding plans become living documentation that improves with every new hire.
