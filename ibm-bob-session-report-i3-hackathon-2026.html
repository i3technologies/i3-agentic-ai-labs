3 · How IBM Bob Was Used

IBM Bob was engaged across the full engineering lifecycle — from architecture decisions through code generation, bug fixing, codebase analysis, and documentation production.

3.1 Agent Mode — Parallel Subagent Execution

Bob's Agent Mode was used to spawn three concurrent subagents to analyse the platform codebase simultaneously, each pulling RAG context from ChromaDB and producing structured JSON findings:

IBM Bob Agent Mode — parallel subagent dispatch ├── backend-scan → FastAPI routes, EvalOS schema, JWT middleware, API contracts ├── frontend-scan → render layer (Markdown, Gantt, taskSync 2-stage gate) └── infra-scan → ArgoCD waves, Tekton pipeline, OpenBao, Keycloak RBAC Each subagent: RAG query → ChromaDB (top-k=10, cosine) → mistral-nemo (Tier 2) → SubagentFinding[] ↓ verify.ts: existsSync() on every filePath + live K8s namespace check ↓ planner.ts: granite-heavy (Tier 1) · confidence gate 0.65 · RampUpPlanSchema (Zod)

4.1 Request Pipeline

6 · Security Implementation

6.1 Lobster Trap Prompt Injection Firewall

Applied to every user-supplied text field before any LLM call. Returns HTTP 400 with matched pattern.

#PatternAttack Type
1ignore (all) previous instructionsClassic prompt injection
2you are now [not i3/onboarding/platform]Persona hijack
3act as [not i3/onboarding/platform]Role override
4system prompt/message/instructionSystem prompt exfiltration
5jailbreakJailbreak attempt
6DAN modeDAN variant
7<script|img|iframe|svgHTML / XSS injection
8drop/delete/truncate tableSQL DDL attack
9SELECT ... FROM ...SQL data exfiltration
10prompt injectionSelf-referential injection
11disregard (all) previousOverride variant
12exfiltrateData exfil intent keyword

6.2 Secrets Management

All secrets injected at runtime from OpenBao KV v2 at path i3/onboarding-agent/ via vault-agent sidecar. Zero secrets in code, zero secrets in git. Protected values: LITELLM_KEY, CHROMA_TOKEN, DIRECTUS_TOKEN, EVALOS_API_KEY, GITHUB_TOKEN, KEYCLOAK_SECRET.
