Critical Blockers

BLOCKER-1 · CRITICAL · orderer-0 CrashLoopBackOff — entire Fabric network non-functional (HC-2)

orderer-msp-bootstrap-deferred.md documents the root cause: MSP crypto material was never generated via fabric-ca-client enroll. Step 1 of the fix (fsGroup + init container for filesystem permissions) is complete ✅. Step 2 (enroll orderer against ford-ca and mount signcerts/keystore/cacerts) is marked ⬜ — not done.

Without a running orderer: no channels exist, no genesis block has been generated, no chaincode can be deployed, no Fabric transactions can be committed. The entire IEBC blockchain audit trail is unavailable.

Impact: P3-GATE-05, P3-GATE-06, P3-GATE-07 all fail. HC-2 (November 2026 staging deadline) is at risk. Resolution (from A9 guide): (1) fabric-ca-client enroll orderer against ford-ca. (2) Package MSP as K8s Secret and mount into orderer-0 StatefulSet. (3) Restart orderer pod. (4) Run configtxgen to produce genesis block. (5) Create ford-channel and join peers. (6) Deploy membership-registry chaincode. Owner: Infra Admin + Blockchain Dev. ETA: 5–10 days.

BLOCKER-2 · CRITICAL · No Go chaincode unit tests (go test ./... produces 0 tests)

platform/ford/fabric/chaincode/membership_registry/ contains only membership_registry.go and go.mod. There is no membership_registry_test.go file. The chaincode-scaffold skill (and HC-2 engineering standards) require every chaincode function to have a unit test using shimtest.MockStub. go test ./... passes vacuously (0 tests, 0 failures) but provides zero evidence of correctness.

Functions requiring test coverage: RegisterMember (idempotency, duplicate check, ward counter increment), VerifyMember (active/revoked/not-found), RevokeMember (idempotent revoke), GetWardCount, GetAgentDutyCount.

Resolution: Author membership_registry_test.go using github.com/hyperledger/fabric-chaincode-go/shimtest. Must cover at minimum: RegisterMember (success, duplicate, missing required field), VerifyMember (active returns true, revoked returns false), RevokeMember (idempotent). Use the template in .bob/skills/chaincode-scaffold/templates/member_registry_test.go. Owner: Blockchain Dev. ETA: ≤ 1 day.

Non-Blocking Warnings

WARN-1 · PDC name mismatch — voteChoicesCollection vs ballotPrivate

The PDC is correctly defined and architecturally separated. However, the canonical HC-8 description, chaincode-scaffold skill, and platform ADRs reference ballotPrivate, while the actual committed name is voteChoicesCollection. Before IEBC audit review, documentation should be aligned to the committed name. Update 01-hard-constraints.md and skill docs to use voteChoicesCollection, or rename the PDC to ballotPrivate and update all references.

WARN-2 · peer0-i3tech needs MSP crypto before it can join channels

Peer is deployed (12-ford-asili-guide.html:639: "Deployed — Needs MSP"). hostPath SCC violation appears resolved by PVC-only storage (ibmc-vpc-block-retain-10iops-tier). Peer still requires fabric-ca-client enroll against i3tech-ca before it can join ford-channel. This is a dependency of BLOCKER-1 resolution, not a separate blocker.

WARN-3 · MEMBER_HMAC_SECRET in K8s Secret, not yet OpenBao-injected (ADR-007 dependency)

ford-api-deployment.yaml pulls secrets from ford-secrets K8s Secret (not via OpenBao agent sidecar). OpenBao path i3/ford/hmac-secret is populated. Until ADR-007 migration completes for ford-secrets, the secret is held in etcd without audit log or rotation TTL. Rotate MEMBER_HMAC_SECRET immediately via the rehash-job pipeline if not done since initial deployment.

WARN-4 · ford-election-agent-v1 manifest absent from Agent Registry

ADR-002 requires ford-election-agent-v1 (state=suspended, autonomy_tier=L0, fabric.invoke in forbidden_tools). Without the manifest, the MCP gateway has no record of FORD agent permissions. Fabric.invoke calls cannot be governance-blocked. This is also a BLOCKER in the Platform Security Gate review (VER-07 memo 2).

WARN-5 · _sessions dict in ussd/handler.py is in-memory (not Redis)

ussd/handler.py:55: _sessions: dict[str, dict] = {} stores session metadata (lang, step, national_id tracking) in memory. A pod restart or scale-out event loses all active USSD sessions. The engineering standards require all session/plan storage to be backed by Redis with TTLs. OTP storage is correctly in Redis; session state must also be migrated to Redis before production load.
