Issues Found & Fixed

✅ RWO PVC DeadLock — Recreate Strategy Applied (3 deployments)

JupyterHub, EduBridge, and SmartLab API all use RWO (ReadWriteOnce) PVCs. The default RollingUpdate strategy causes new pods to get stuck in ContainerCreating because the PVC can only attach to one node at a time. All three patched to strategy: Recreate. SmartLab stuck pod deleted and rollout confirmed clean 1/1 Running.

✅ SmartLab → SeaweedFS/Directus/n8n Blocked (NetworkPolicy)

i3-ott namespace had deny-all-ingress with no rule for i3-smartlab. Added 4 NPs: allow-smartlab-to-seaweedfs, allow-smartlab-to-seaweedfs-filer, allow-smartlab-to-directus, allow-smartlab-to-n8n. All 8 dependencies now reachable: 8/8 TCP OK

✅ SmartLab → LiteLLM + Voice STT/TTS Blocked (NetworkPolicy)

Patched allow-gateway-clients and allow-llm-clients in i3-model-gateway to include i3-smartlab. Patched voice-ingress in i3-voice similarly. LiteLLM liveliness confirmed 200; STT/TTS /docs confirmed 200.
