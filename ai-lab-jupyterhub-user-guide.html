1 — Overview

The i3 AI Lab provides a managed JupyterHub environment for data science, machine learning experimentation, and AI application development. All computation runs on-cluster inside IBM ROKS (OpenShift) in Frankfurt, and all AI model inference is served from the on-cluster Ollama + LiteLLM gateway — no external API keys or egress required for AI features.

2 — Login & Spawning a Server

  1. Navigate to https://jupyter.i3technologies.co.ke.
  2. Click Sign In with i3 SSO and log in with your @i3technologies.co.ke credentials.
  3. JupyterHub presents a server options form. Select a profile (Standard or Large) and click Start.
  4. Your personal notebook server starts in approximately 30–60 seconds. You are redirected to the JupyterLab interface.
NoteYour notebook server automatically shuts down after 60 minutes of inactivity to conserve cluster resources. Your files are persisted on a PVC and will be available next time you spawn a server.

3 — Working with Notebooks

3.1 Creating a Notebook

  1. In JupyterLab, click the + button (Launcher) or File → New → Notebook.
  2. Select a kernel: Python 3 (ipykernel) is the default and recommended kernel.
  3. Rename your notebook by right-clicking the tab and selecting Rename.

4 — Available AI Models (LiteLLM)

All models are served via the LiteLLM proxy at http://litellm-proxy.i3-model-gateway.svc.cluster.local:4000. Use the alias names below in your API calls.

AliasUnderlying ModelBest For
granite-nanogranite3.1-dense:2bFast classification, short Q&A, lightweight tasks
qwen-fastqwen2.5:7b-instruct-q4_K_MGeneral purpose — summaries, drafting, analysis
qwen-heavyqwen2.5:14b-instruct-q4_K_MComplex reasoning, long-context tasks
coderqwen2.5-coder:7b-instruct-q4_K_MCode generation, debugging, code review

embednomic-embed-text:latestText embeddings for RAG and semantic search
NoteAll models run on CPU with Q4/Q5 quantisation. First-token latency is 5–30 seconds depending on model size. Use granite-nano or qwen-fast for iterative experimentation.

5 — Calling AI Models in Notebooks

5.1 Using the OpenAI-Compatible API

from openai import OpenAI

client = OpenAI(
    base_url="http://litellm-proxy.i3-model-gateway.svc.cluster.local:4000",
    api_key="sk-i3-internal"  # LiteLLM master key — already set as env var LITELLM_API_KEY
)

response = client.chat.completions.create(
    model="qwen-fast",
    messages=[{"role": "user", "content": "Summarise the key principles of data governance."}]
)
print(response.choices[0].message.content)

5.2 Using the LiteLLM Python SDK Directly

import litellm
import os

litellm.api_base = "http://litellm-proxy.i3-model-gateway.svc.cluster.local:4000"
litellm.api_key = os.environ.get("LITELLM_API_KEY", "sk-i3-internal")

response = litellm.completion(
    model="openai/coder",
    messages=[{"role": "user", "content": "Write a Python function to parse a CSV and return a pandas DataFrame."}]
)
print(response.choices[0].message.content)

5.3 Generating Embeddings

response = client.embeddings.create(
    model="embed",
    input=["The quick brown fox jumps over the lazy dog"]
)
vector = response.data[0].embedding
print(f"Embedding dimensions: {len(vector)}")

5.4 Vision (Image Input)

import base64

with open("chart.png", "rb") as f:
    img_b64 = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model="vision",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "Describe this chart and identify the key trend."},
            {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{img_b64}"}}
        ]
    }]
)
print(response.choices[0].message.content)

9 — Best Practices

  • Start small: Use granite-nano or qwen-fast for prompt prototyping before switching to qwen-heavy.
  • Streaming: For long responses add stream=True to your completion call to receive tokens incrementally and avoid gateway timeouts.
  • Chunk large documents: LLMs have a context window. Split large PDFs into 500-token chunks before passing to the model.
  • Clear kernel output before committing notebooks to Git — avoid leaking data in cell outputs.
  • Shut down idle servers: Use File → Hub Control Panel → Stop My Server when done to free cluster resources for other users.
  • Version your notebooks: Use the nbgit extension or commit to your personal GitHub repo regularly.

10 — Troubleshooting

IssueFix
Server spawn times outCluster may be under load. Click Stop Server and try again in 2 minutes. If persistent, contact support.
Kernel dies mid-executionMemory limit exceeded. Reduce dataset size or use chunked processing. Switch to a "Large" server profile if available.
LiteLLM returns connection errorVerify the base URL uses the cluster-internal DNS: http://litellm-proxy.i3-model-gateway.svc.cluster.local:4000. External URLs are not accessible from within pods.
Model response very slowCPU inference — expected. Use a smaller model alias (granite-nano) for faster responses during development.
File upload failsFiles over 500 MB cannot be uploaded via the browser. Use the JupyterLab Terminal to wget or curl large files from accessible sources.
Package install not persistingUse %pip install (not !pip install) to ensure packages install into the correct user-space environment.
